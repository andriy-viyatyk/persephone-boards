## Goal

Move Agent Chat enrollment into the Wake Word board, where the user can inspect, listen to and adjust a recorded phrase before saving its embedding. Make unusually long existing samples visible and improve automatic public enrollment crops.

## Background

- `boards/wake-word/scripts/service.mjs:13,491-508,606-669` captures 40,000 samples at 16 kHz (2.5 s), then immediately assesses and encodes. `quality()` uses 100 ms RMS slices, the 20th-percentile noise floor, and `max(0.006, 2.4 × noise)`; the first and last active slices define a **loudness**, not speech, crop. A click or burst can include the intervening noise. It also rejects silence, short spans and excessively high or low peaks.
- Reported local measurements: one `agent-wake` sample has 30 embedding steps beside three with 8–9, and an `agent-stop` sample has 20; Agent Chat Wake mode false-triggers during typing with phone-played noise. This is a reported observation, not proof of a single cause. Users currently cannot inspect their captured audio.
- `boards/wake-word/scripts/engine.mjs:48-73,155-179` implements Silero with a carried LSTM state and mandatory 64-sample context, and 80 ms embedding steps. `service.mjs:191-209` already uses the VAD for detection. `app.js:236-274` opens the private enrollment channel and waits for the terminal result.
- `C:/projects/persephone/assets/guides/agents/speech-wake.md:57-74` defines public enrollment as automatic capture followed by one `enrolled` message, without a review handshake. Use the improved VAD suggestion for both paths; only the private path adds review. Keep public enrollment's result behavior and `list` compatible.
- Agent Chat duplicates enrollment in `boards/claude-agent/index.html:90-111` and `app.js:1676-1960`. Its `wake-assistant.js:195-207,243` checks that `agent-wake` exists and listens for both phrases; `agent-stop` remains optional. Keep those listening semantics and configuration while removing enrollment management from Agent Chat.
- The audio-filter lab at `C:/projects/persephone/.persephone/boards/audio-filter-lab/` is gitignored in another repository: `index.html:7`, `app.js:97-133`, and `spectrogram.js:1-78` show the requested waveform and 1024-point Hann-window FFT, 0–8 kHz spectrogram. Port/adapt locally, never import that path; no new third-party library or download is needed. The lab uses theme colors for the spectrogram.
- The clip must be the exact audio delivered by `audio@1`, the same stream the detector uses with matching capture settings. In Persephone 5.0.19 the managed microphone pipeline can apply notch and DeepFilterNet cleaning; `C:/projects/persephone/src/renderer/audio/audio-window.ts:55-84,220` and `src/renderer/ui/speech/MicrophoneAudioPipeline.ts:58-63` show cleaning is configurable and can fall back, so do not promise it always ran.
- The live boards guide describes ordered two-way service channels with a 1 MiB service-to-page message limit and `writable`/`whenWritable()`. `C:/projects/persephone/src/main/board-protocol-service.ts:73-94` allows local scripts and `media-src 'self' blob:`; an in-memory Web Audio buffer needs no media URL or network permission. Verify playback and autoplay behavior in the running app; CSP alone does not prove playback works. The manifest already grants service, microphone, computer audio and `audio@1`, with network and filesystem disabled.

The host opening mechanism already exists and shipped in Persephone 5.0.18; no new host API or bridge-version bump is required. Source evidence and routing details:

- `C:/projects/persephone/src/board-shim.ts:2483-2484` forwards `openBoard(folder)` only; `src/main/board-bridge.ts:726-747` resolves it with `intent: "list"` and granted filesystem permissions. Agent Chat's manifest has `fileSystem: false`, and this API has no payload. `board-open-content.ts:63` explicitly refuses another board.
- The existing unified capability route is page-based: `src/main/capability-router.ts:226-234,327-362` authorizes the declared `open`, validates a single JSON payload and dispatches to the selected board. `src/renderer/api/board-capability-transport.ts:126-169,203-215` selects an existing page in the caller's window or opens the provider's board; `src/renderer/api/pages/PagesLifecycleModel.ts:393-428` opens the handler page. With reuse enabled, `board-capability-transport.ts:153-169,273-285` focuses an already open page and queues each new request.
- On a new page `board-capability-transport.ts:232-241` stores the initial intent and `src/renderer/editors/board/BoardWebview.ts:800-817` includes it in the frame handshake. On reuse `BoardWebview.ts:1230-1255` posts `capabilities:intent` with the payload. `src/board-shim.ts:1012-1055,2249-2260` delivers both through `persephone.intent.onRequest(request)`, with data at `request.payload`. Settle via request-bound `resolve` or `reject` promptly. No query string, hash or filesystem access is needed.
- `assets/guides/agents/capabilities.md:9,48-50,100-111` records the bridge 1.51.0 consumer minimum, exact `uses` grant, provider selection and trust checks. Both boards must be trusted and enabled; the additional grant appears in the normal permissions flow. The Wake Word page validates every payload and does not rely on caller-supplied identity as authorization. The grant authorizes messaging, not audio or file access; `agent: false` prevents agent invocation. `src/shared/board-bridge-version.ts:2` currently reports `1.53.0`; no increment is needed.

## Concerns / Open Questions

- VAD thresholds and 100 ms margin are initial design choices; calibrate on real speech, including quiet words and false-positive clicks. Fallback may still include clicks; the review lets the user inspect and adjust the selection. Public callers receive the automatic crop without review.
- Capability routing can select a different installation from the active speech provider if their provider bindings diverge. Match provider keys and test multiple installations; when correlation is unavailable, fail visibly rather than silently configuring the wrong enrollment store.
- Existing length is quantized and cannot reconstruct exact crop edges; versions with different frontend semantics must not use this formula. No audio exists to replay old samples.
- Closing during an in-flight filesystem write can race with persistence; the cancellation guarantee applies before commit, not after an already completed write. Ensure the UI communicates the saving state.
- Cleaning depends on host settings and fallback behavior; compare enrollment and listening with identical device and echo cancellation settings.
