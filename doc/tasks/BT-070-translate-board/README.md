## Goal

Finish the `translate` board as a local `text.translate@1` provider: expose the normative service contract over Persephone service channels, add CLD2 detection, and provide a language manager and paste-text test panel. Ship the board as v1.0.0, with model files kept in Persephone's per-user board-data cache.

## Background

- **Product decisions:** [EPIC-135](../../../../persephone/doc/epics/EPIC-135.md), especially [Browser behaviour](../../../../persephone/doc/epics/EPIC-135.md#browser-behaviour-user-decision-2026-10-27), [Proof of concept](../../../../persephone/doc/epics/EPIC-135.md#proof-of-concept-2026-10-27), and [Plan → Translate board](../../../../persephone/doc/epics/EPIC-135.md#translate-board). Translation is explicit; pages and editor text are detected; the board owns engine/models/downloads/caller policy; non-English pairs pivot through English.
- **Normative wire contract:** [`text-translate.md`](../../../../persephone/assets/guides/agents/text-translate.md), authored by [US-1734](../../../../persephone/doc/tasks/US-1734-text-translate-contract/README.md). Implement its declarations, one-operation-per-channel lifecycle, exact messages, close/cancel behavior, limits, errors, priorities, and caller approval requirements. Treat the guide as authoritative if an older task note differs.
- **Engine:** [BT-069](../BT-069-bergamot-runtime/README.md) adds `boards/translate/scripts/bergamot-runtime.mjs`, `translation-assets.mjs`, and `bergamot-worker.mjs`. The runtime owns Firefox Bergamot WASM, Remote Settings model discovery/download/cache, pivoting and idle worker unload. `TranslationAssets.getPair()` verifies an installed model or downloads it when absent. `BergamotRuntime.translate()` currently calls `getPair()` for each direct or pivot leg, so using it directly from the provider would violate the contract's MUST NOT download rule.
- **Important BT-069 integration change:** add an installed-only asset lookup (for example `getInstalledPair(from, to, { selection })`) and a guarded runtime translation path that accepts already verified direct/pivot model files and never calls `getPair()`. The provider first resolves the route from one registry selection and checks every required leg through that installed-only path; if any is absent, return terminal `not-ready` before enqueueing work. The runtime guard is required as the final invariant against accidental implicit downloads/races. Keep explicit `download()` as the sole route to `getPair()`. Do not implement readiness by calling `translate()` and catching the later download, since that has already started a fetch. Refresh description/management state after successful download or removal.
- **Per-item format integration:** the contract allows `format: "text" | "html"` on every item, while BT-069 `translate()` accepts one `html` boolean for the entire call and the worker applies it to all items in that call. Partition a service batch into text and HTML groups, run each group with the matching runtime flag, then merge results by original key/order. Preserve each item's independent failure as `{key, ok:false, error}`; a failed format group must not discard successful siblings. Preserve each input key exactly and send progress based on completed original items, not group-local indices. Keep internal Bergamot sub-calls within BT-069's 8-item / 8,192 UTF-16-unit caps.
- **Detection PoC and code normalization:** `C:\projects\translate-poc\detect.mjs` runs the vendored Firefox `cld2__cld-worker.js` in a Node `vm` context with its matching `.mem` data, then calls CLD2's exported detector and extracts up to three language candidates, score percentages and its reliability flag. The worker's result exposes raw language codes through its main `language` and each candidate's `languageCode`. For BT-070, place that CLD2 loader/detector inside a dedicated `node:worker_threads` worker as EPIC-135 specifies; do not run detection on the UI thread or block the service event loop. Vendor `vendor/cld2__cld-worker.js`, `vendor/cld2__cld-worker.js.mem`, and `vendor/cld2__LICENSE` from `C:\projects\translate-poc\vendor\`; the inspected license is Apache-2.0. Retain source/provenance notes and license in the board ZIP. Normalize all detected and candidate codes against the language codes actually advertised by `translations-models-v2.json`: the saved snapshot has 404 records, 115 directed pairs and 59 distinct codes, including `zh-Hans` and `zh-Hant` (but not `zh`). Map CLD2 `zh` to `zh-Hans`; map legacy aliases such as `iw`→`he`, `in`→`id`, `no`→`nb`, and `fil`→`tl` when that destination exists in the registry. Map `jw`→`jv`, but since neither `jv` nor `jw` is in this snapshot's registry, retain canonical `jv` as a detected-but-unsupported code rather than inventing a model route. Define mappings from the CLD2 worker's raw codes to registry codes, and leave canonical codes unchanged when no registry code exists so consumers can report “not supported.” Map CLD2 reliability to contract `high`/`low` confidence.
- **Reference board:** follow [`boards/speech-to-text`](../../../boards/speech-to-text/): manifest service declaration, `service.mjs` channel setup and early-message handling, management channel with snapshots/download/cancel/remove/progress, loading settings at startup plus `onChange`, caller policy, model controls, localized UI, README and `WHATS-NEW.md`. It uses `persephone.service.onChannel` for providers and `persephone.service.openChannel()` for same-board management. Keep UI actions and explicit model acquisition on the board page.
- **App compatibility:** `C:\projects\persephone\package.json` on the `upcoming-v5.0.15` line says version **5.0.15**. Set `minAppVersion` to `5.0.15`, the release carrying US-1734. The live Boards guide says service channels need bridge 1.42.0; set `minBridgeVersion` at least `1.42.0` unless implementation uses a newer bridge feature.
- **Language labels decision:** build language choices from the model registry and use the board UI language (`persephone.locale.code`, English initially, following the board's i18n language pack) as the locale for `Intl.DisplayNames([boardUiLanguage], { type: "language" })`. These user-readable names are primary; the endonym may appear as secondary text. Keep the BCP-47/model code visible as well, and fall back to that code if display-name lookup fails. The target runtime check in Node produced distinct English labels “Simplified Chinese” and “Traditional Chinese” for `zh-Hans` and `zh-Hant`; still verify this in the supported Chromium runtime and add script disambiguation if that runtime renders identical names.

## Implementation Plan

All paths below are within `boards/translate/` unless stated.

- [x] **Close the BT-069 no-download gap.** Add verified installed-only route lookup for direct and English-pivot legs to `scripts/translation-assets.mjs` / `scripts/bergamot-runtime.mjs`. Refactor runtime translation to receive only resolved installed files or an explicit installed-only option that cannot fall back to `getPair()`. Keep `getPair()` reachable only from explicit download operations. Preserve one stable registry selection for route and size calculations across an operation.
- [x] **Vendor CLD2 and normalize codes.** Copy the two PoC CLD2 runtime files and Apache-2.0 license into `vendor/cld2/`; add `NOTICES.md` with Firefox/CLD2 source provenance, upstream file names and unchanged/modified-file status. Add `scripts/cld2-worker.mjs` to initialize the Firefox worker script in the worker thread, transfer detect requests/results, and support cancellation/clean shutdown. Add a small `scripts/language-detection.mjs` facade to bound the sample to 4,096 characters, normalize main and candidate raw CLD2 codes against the exact `translations-models-v2.json` code set, cap candidates at three, expose sample character count, and translate CLD2 confidence/reliability into the contract shape. Include at least `zh`→`zh-Hans`, `iw`→`he`, `in`→`id`, `no`→`nb`, `jw`→`jv`, and `fil`→`tl` mappings where destination codes exist; explicitly leave unsupported canonical results such as `jv` without a model route. Keep the map tied to registry codes rather than assuming CLD2's code spelling matches model IDs. Do not load other detection engines from the PoC.
- [x] **Normalize `htmlLang` and resolve disagreement.** Canonicalize `htmlLang` to the model code set before using it: normalize region aliases such as `zh-CN`/`zh-SG`→`zh-Hans`, `zh-TW`/`zh-HK`→`zh-Hant`, and reduce ordinary region variants such as `en-US`→`en`, `pt-BR`→`pt`; preserve an exact supported script code. For a valid normalized `htmlLang` that disagrees with CLD2, use a confident/high CLD2 result as EPIC-135's Browser behaviour specifies; when CLD2 is low-confidence, unknown, or unsupported, prefer the valid normalized `htmlLang` as the page's language. Return normalized language/candidate codes in the contract response. If neither source resolves to a registry language, report the normalized detected code as unsupported rather than silently substituting a different model.
- [x] **Implement the provider in `scripts/service.mjs`.** Start one `BergamotRuntime` with the configured idle timeout, create the CLD2 worker, load settings at startup and subscribe to changes, then register `persephone.service.onChannel`. Accept only `text.translate` v1 cross-board channels and same-board management channels; use `info.interface` for cross-board identity and enforce `caller-approval-policy` for every `describe`, `detect`, `translate`, and `download`. Refuse disallowed callers with `connection-refused`. Apply `accept-granted` and `same-board-only` semantics as in Speech to Text; do not infer permission from an open channel alone.
- [x] **Match each operation and terminal response exactly.** `describe` sends `{type:"description", engine, model, pairs, features}` and closes; enumerate directed model pairs only, with `installed` and total advertised download `sizeBytes`. `detect` accepts `text` and optional `htmlLang`, returns normalized `language`, `confidence`, actual `sampleChars`, and up to three descending candidates, then closes. `translate` returns exactly one terminal `result` or request-wide `error`; key each per-item result/error. When `from` is omitted, detect a bounded sample assembled from that batch before resolving/preflighting its route. `download` is the only operation allowed to fetch; support direct pairs and two-leg English pivots, identify each leg in progress, and return `download-result` only after all requested legs are installed. Reject unknown operations rather than interpreting them as another operation.
- [x] **Enforce all v1 bounds before scheduling.** For translation: require a non-empty batch ID and target, unique keys, supported format values, at most 32 items, at most 64,000 Unicode code points across item text, and serialized open-message size below 1 MiB. Reject over-limit input as whole-request `too-large`; never truncate. For detection, cap samples at 4,096 characters and report the sample actually inspected. Preserve item/key association and isolate item failures. Map stable errors: absent installed leg → `not-ready`; no direct or English route → `unsupported-language-pair`; invalid format → `unsupported-format`; size violation → `too-large`; engine/detector failure → `engine-failed`; fetch/verification failure → `download-failed`; user/channel cancellation → `cancelled`.
- [x] **Implement the provider priority queue and cancellation.** Queue accepted translation batches by `visible`, `near`, `background` priority and FIFO order within each priority; reorder queued jobs only, never an active call. Emit `{type:"progress",id,done,total}` as original items finish. A `{type:"cancel"}` or close aborts only that channel's active work and removes its queued job; a download cancel aborts only that download. Closing the provider channel releases its queue entry and abort signal. Honor `channel.writable` / `whenWritable()` on every streamed progress message. Do not add `scope` to the protocol; clients own scope grouping and close all their operation channels when their page/document ends. Keep engine execution serialized if needed by the single Bergamot worker, while retaining queued priority order.
- [x] **Bridge engine results with per-item formats.** Preflight all route legs with installed-only lookup before queue acceptance. Group the batch into text and HTML calls to honor BT-069's call-wide `html` flag; translate each group independently, then reassemble in original input order. Catch item/group failures and return sibling successes. Emit progress by completed input item count, not by internal runtime fragments. A format group with an engine-wide fault may mark its members `engine-failed`, but must preserve successful results from the other group.
- [x] **Expose a same-board management channel.** Follow Speech to Text's management snapshot pattern. It returns available directed pairs, advertised sizes, verified installed state, active downloads/legs and byte progress. Commands list/refresh, download, cancel, and remove. Removal is pair/version-scoped through `runtime.remove()` and refreshes state. Keep model payloads under `%LOCALAPPDATA%\Persephone\board-data\translate`, never in the installed board directory. Unload the Bergamot worker on the BT-069 default idle timeout (3 minutes; bounded 1–120) so its grown WASM heap is released.
- [x] **Build the language manager and test panel.** In `index.html` / `app.js` / `app.css`, list one row per supported non-English language, sorted by its primary display name, with a filter box. Do not render the roughly 115 directed pairs as rows. Each row has two independent directions: **Translate from <language>** (`<language>`→`en`) and **Translate into <language>** (`en`→`<language>`); each direction shows its own advertised size, installed state, progress and Download/Cancel/Remove actions. Derive direction availability from the registry; if a direction has no model, show it as unsupported/disabled instead of implying installation can provide it. Do not show English as a language row. State in the manager that any two non-English languages can translate through English when both directed legs are installed. Add a paste-text panel that detects source language, shows confidence/candidates and permits source correction, selects target language, and translates into a separate result area; show whether the selected route is direct or pivots through English and which legs must be installed. If the test panel offers to acquire missing models, ask the user before invoking explicit `download`; never let the Translate action itself trigger a fetch. Use DOM text APIs and retain the board theme variables from `board-base.css`.
- [x] **Declare the board in `board-manifest.json`.** Set id/folder `translate`, name/author/repository, version `1.0.0`, `minAppVersion: "5.0.15"`, `minBridgeVersion` for service channels, `service: "scripts/service.mjs"`, `serviceInterfaces: [{"id":"text.translate","version":1,"title":"Text Translation"}]`, and service permission. Keep permissions minimal: no renderer `network` bridge permission is needed for Node service downloads; no microphone/camera, app scripting, or board file-system grant is needed. ## Concerns / Open Questions

- **BT-069 API change is required:** its current route resolution calls download-capable `getPair()` from `translate()`. The service must preflight installed models, and the runtime must expose an installed-only guard so no translation path can download, even after future refactors.
- **Mixed format batches:** runtime calls have one HTML flag, but wire requests mix formats per item. Group by format, then restore original keyed order and count progress by input item.
- **Display names:** use `Intl.DisplayNames` in the board UI locale as the primary name so users can identify languages they do not read; an endonym is optional secondary text. Verify that target Chromium renders `zh-Hans` and `zh-Hant` distinctly; add “(Simplified)” / “(Traditional)” disambiguation if it does not.
- **Code interoperability:** the source/target values sent to Bergamot must use the model registry's spellings. Confirm the alias table against the vendored CLD2 worker's returned code names and the saved model snapshot; preserve unsupported canonical codes (for example `jv`, absent from the snapshot) so consumers can report that no translation model is available.
- **`htmlLang` precedence:** normalize language/region/script subtags to registry codes first. When a normalized page hint conflicts with high-confidence CLD2, CLD2 wins; if CLD2 is low-confidence or unusable, use the valid page hint. This matches EPIC-135's explicit browser rule.
- **Language manager scale:** the verified saved snapshot contains 115 directions but only 59 distinct language codes. Keep the manager language-oriented (58 non-English rows), with separate English-inbound and English-outbound model actions per row.
- CLD2's vendored worker depends on its companion `.mem` data; include both and the Apache-2.0 license. Keep detection in a worker thread as called for by EPIC-135.
- The provider discovers model sizes from the current Remote Settings selection; `describe.pairs` remains a list of direct directed models, while route resolution and pivot downloads are service behavior. Keep advertised byte totals consistent with BT-069's compressed download sizes.
- Persephone package version is verified as 5.0.15. If US-1734 is ultimately released in a different app version, revisit `minAppVersion` before publishing.

## Notes

- Verified source behavior: BT-069's `BergamotRuntime.translate()` resolves direct or pivot legs through `assets.getPair()`; `getPair()` calls `#verifiedManifest()` and then downloads when the verified manifest is absent. The required runtime change above is not optional for contract compliance.
- Verified format behavior: `BergamotRuntime.translate({ ..., html })` sends one boolean to its worker; `bergamot-worker.mjs` applies that boolean to each `ResponseOptions` entry in the call. Service grouping is therefore necessary.
- Verified CLD2 PoC behavior: `detect.mjs` runs the vendored Firefox worker script and `.mem` sidecar through a Node VM, whose message handler returns its main result, up to three candidate languages and confidence/reliability; EPIC-135 records successful Japanese, `zh`, and `zh-Hant` detections. BT-070 wraps this loader in a Node worker thread. The saved 404-record model snapshot has 59 distinct codes and 115 unique directions; its Chinese models use `zh-Hans`/`zh-Hant`, not generic `zh`.
- Spot-checked PoC worker outputs on language samples: raw CLD2 results included `iw`→`he`, `in`→`id`, `no`→`no`, and `fil`→`tl`. The current model snapshot has `he`, `id`, `nb`, `nn`, and `tl`, but no `no`; therefore the specified compatibility table maps CLD2 `no` to model `nb`. The sample did not establish a `jw` result, so keep `jw`→`jv` as an explicit legacy-code mapping and treat `jv` as unsupported by this snapshot (neither `jw` nor `jv` is present).
- Verified display names in the available Node Intl implementation using English locale: `zh-Hans` renders “Simplified Chinese” and `zh-Hant` renders “Traditional Chinese,” so the names are distinct here. The board must confirm the bundled app's Chromium implementation and retain a visible script suffix fallback.
- Verified license: PoC `vendor/cld2__LICENSE` identifies Apache License 2.0. Preserve a copy with the vendored worker and data file.
- Verified reference details: Speech to Text uses `minAppVersion: "5.0.15"`, a `caller-approval-policy` enum and `idle-unload-minutes`, loads initial setting values at startup, and provides a same-board management channel with progress and asset actions. Reuse that lifecycle structure, adapting it to directed model pairs and this provider contract.
- Task-document pass only: no board implementation or tests are included here.
