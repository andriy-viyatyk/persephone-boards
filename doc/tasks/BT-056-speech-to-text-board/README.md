## Goal

Create the `speech-to-text` board as a local `speech.transcribe` v1 provider backed by whisper.cpp v1.9.5. The board lets the user explicitly install a pinned runtime and multilingual model, test their microphone, and use the provider without sending audio off the computer.

## Background

- Binding product decisions are in [EPIC-133](../../../../persephone/doc/epics/EPIC-133.md): Speech to Text board, the engine measurements, Concerns 4–6, and the Notes decisions. V1 records then transcribes; it does not provide live partial text or auto-stop. `maxAudioMs` is five minutes. Downloads are explicit, models/runtime stay out of the board ZIP, and audio is local.
- The normative provider contract is [`speech-transcribe.md`](../../../../persephone/assets/guides/agents/speech-transcribe.md). Follow its approval-first rule, `describe`, immediate pre-accept `not-ready`, immediate `listening`, audio buffering, optional `preparing`, `transcribing`, one `result` or terminal `error`, streaming `too-long`, cancellation, and close semantics. Consumers can send audio before `listening`; do not require them to wait for it.
- `whisper-server` source is pinned at [whisper.cpp v1.9.5 `examples/server/server.cpp`](https://raw.githubusercontent.com/ggml-org/whisper.cpp/v1.9.5/examples/server/server.cpp). It registers multipart `POST /inference`, requires multipart file field `file`, reads WAV without `--convert`, and supports the multipart fields `offset_t`, `offset_n`, `duration`, `max_context`, `max_len`, `best_of`, `beam_size`, `audio_ctx`, `word_thold`, `entropy_thold`, `logprob_thold`, `no_speech_thold`, `debug_mode`, `translate`, `diarize`, `tinydiarize`, `split_on_word`, `no_timestamps`, `token_timestamps`, `language`, `detect_language`, `prompt`, `carry_initial_prompt`, `response_format`, `temperature`, `temperature_inc`, `suppress_non_speech`, `suppress_nst`, `vad`, `vad_threshold`, `vad_min_speech_duration_ms`, `vad_min_silence_duration_ms`, `vad_max_speech_duration_s`, `vad_speech_pad_ms`, `vad_samples_overlap`, and `no_language_probabilities`. V1 needs `file`, `response_format=verbose_json`, `language`, `prompt`, `temperature=0.0`, `no_timestamps=true`, and `no_language_probabilities=true`; do not enable translation.
- The server accepts `language=auto`: `whisper_params_parse` exempts `auto` from `whisper_lang_id()` validation, and inference detects the language. In `verbose_json`, the `language` field is the full name returned by `whisper_lang_str_full(whisper_full_lang_id(ctx))`. Set `no_language_probabilities=true`: otherwise v1.9.5 calls `whisper_lang_auto_detect()` after inference to populate `language_probabilities`, causing a second encoder pass (~1 s GPU / ~9 s CPU). Copy the pinned v1.9.5 `src/whisper.cpp` id -> short code -> full name mapping into `scripts/whisper-languages.mjs`; map the returned full name to its ISO code, return a sole caller hint unchanged, and return `""` for an unknown name.
- A v1 `languages` array cannot be passed as-is because whisper-server has one `language` field. Rule: zero hints or two-or-more hints map to `language=auto`; exactly one valid hint maps to that code. This keeps multi-language requests in detection mode instead of silently treating the first hint as a forced language. The board’s `language-hints` setting seeds the test recorder only; an absent/empty contract field remains auto-detect.
- Runtime release evidence is in [`BT-055`](../BT-055-whisper-runtime/README.md#release-result-2026-10-26): tag `whisper-runtime-1.9.5-r1`, archive size 19,958,389 bytes, SHA-256 `f3db3e57713053721a85ea2269221db8b2b3bfda026fcec40442911566e1d046`. Its ZIP root includes `whisper-server.exe`, required DLLs, `README.txt`, `manifest.json` (hashes every other payload file), and `licenses/`. The runtime uses dynamic Vulkan plus CPU backend DLLs; `--no-gpu` selects CPU.
- Models are downloaded from Hugging Face’s `ggerganov/whisper.cpp` repository and are multilingual (no `.en` assets):

  | Model file | Bytes | SHA-256 | Choice |
  |---|---:|---|---|
  | `ggml-large-v3-turbo-q5_0.bin` | 574,041,195 | `394221709cd5ad1f40c46e6031ca61bce88931e6e088c188294c6d5a55ffa7e2` | Default |
  | `ggml-small-q5_1.bin` | 190,085,487 | `ae85e4a935d7a567bd102fe55afc16bb595bdb618e11b2fc7591bc08120411bb` | Weaker machines |
  | `ggml-base-q5_1.bin` | 59,707,625 | `422f1ae452ade6f30a004d7e5c6a43195e4433bc370bf23fac9cc591f01a8898` | Lowest memory |

- Download persistent files under `%LOCALAPPDATA%\Persephone\board-data\speech-to-text\`, with `runtime/` and `models/` children. This follows the service’s sanitized environment (`LOCALAPPDATA` is allowlisted in `module-service-supervisor.ts`) and Agent Chat’s `GROUP_ROOT()` convention in `boards/claude-agent/scripts/service.mjs`. It sits outside the installed board folder, which Persephone replaces during board updates. Store only small shared settings/progress metadata in `persephone.storage`; never put model/runtime bytes there.
- A declared service runs with Node built-ins including filesystem, networking, child processes, streams, and timers; it receives `PERSEPHONE_BOARD_ROOT` and the Windows environment allowlist. The guides say `network: false` denies `persephone.fetch()`. Agent Chat’s manifest keeps `network: false` while its Node service downloads a pinned SDK directly, confirming that service Node networking is independent of the bridge network permission. Request only `service: true` and `microphone: true`; the page needs the latter only for its test recorder. No `execute`, `fileSystem`, `network`, or `appScripting` grant is needed.
- Channel APIs and service settings access require bridge `1.42.0`; the service-channel guide and closest precedent use `minBridgeVersion: "1.42.0"`. The reserved interface ships in app `5.0.15`, so use `minAppVersion: "5.0.15"` as specified.
- Closest precedent: [`boards/claude-agent/`](../../../boards/claude-agent/) has the same `scripts/service.mjs`, channel lifecycle, persistent service data under `LOCALAPPDATA`, manifest settings and service declarations, `lang/en.json`, `i18n.js`, `board-base.css`, `WHATS-NEW.md`, `CLAUDE.md`, and `README.md` layout. Follow those idioms. Use Mneme’s [`ModelPanel.ts`](../../../../persephone/src/renderer/editors/mneme-config/ModelPanel.ts) only for its status/progress/list layout.
- The board authoring guide says board CSP uses local `script-src 'self'` and `worker-src 'self'`; `connect-src 'self'` blocks remote page requests. Load a same-origin `audio-capture-worklet.js` with `audioWorklet.addModule()` rather than a blob URL. The runtime source confirms the board CSP explicitly sets `worker-src 'self'`; network downloads belong in the service, not page `fetch()`.

Fixed during verification (by Claude):

- `downloads.mjs`: the runtime `manifest.json` is `{ upstreamTag, upstreamCommit, files }`, not an array; both verifiers read `files` through `manifestFiles()`.
- `service.mjs`: the host drops channel messages that arrive before a handler is registered, and `onChannel` awaited the readiness checks first, so audio and `end` sent right after connect were lost. Messages are now collected from the first line and replayed once the request is accepted (also for management channels).
- `service.mjs`: the runtime was re-hashed on every request; the result is cached and cleared on install and remove.
- `service.mjs` + `app.js`: license links pointed into the board folder, but the runtime lives under `LOCALAPPDATA`; notices are now fetched over the management channel (`license` / `license-text`) and shown in expandable rows.
- `app.js` + `index.html`: the error panel sat below the fold (the first runtime failure was invisible); it is now under the header. The management channel reconnects after a service restart instead of staying dead.
- `app.js`: the recorder status stayed "Transcribing…" after the result; it now says done.
- Persephone `assets/guides/agents/speech-transcribe.md`: the rule and the provider example now register `onMessage` before any `await`.

Not verified live: GPU off (`use-gpu` false → `--no-gpu`), idle unload after 10 minutes, the shutdown process-tree kill, a cross-board caller (BT-057 provides one), and a real spoken recording through the test recorder (needs the user's voice).

Observations, not fixed: the level meter is linear RMS, so normal speech fills only a few percent of the bar; a cancelled download shows plain "Not installed" without saying a partial file will resume; the platform logs `Board settings subscription failed: service-exited` on every service stop (Agent Chat's log has it too).
