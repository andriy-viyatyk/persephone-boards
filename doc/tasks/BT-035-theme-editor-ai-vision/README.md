## Goal

Publish a board AiVision model at `pages[pageId].editor.app` so the user's connected AI agent can inspect and edit the Theme Editor's live draft, preview changes in the open editor, and manage themes through the existing `persephone.themes` bridge. The model must stay synchronized with UI edits and must never wait for an in-board dialog.

## Background

- **Why this is useful alongside `app.themes`:** an agent can already call Persephone's app-level theme service, but that edits persisted themes independently. This model acts on the draft the user has open, including unsaved edits, and collaborators can see those edits and the resulting preview update in the Theme Editor UI.
- BT-034 has implemented the editor in `boards/theme-editor/app.js` and `index.html`. Its local `state` contains `themes`, `current`, `draft`, `baseline`, `sourceId`, `sourceKind`, `derived`, `displayed`, `contrast`, `hasPreview`, `previewSuperseded`, `dirty`, and `busy`. `onDraftChanged()` reads the visible name field, recomputes dirty state, and calls `queueDraftRefresh()`. That function validates, debounces, serializes preview work through `previewChain`, and requests authoritative `derive()`, `contrast()`, and (for edits) `preview()` results from Persephone.
- Current editor operations to reuse are `loadSource(id)`, `queueDraftRefresh()`, `saveDraft(saveAs)`, `applySource()`, and `revertDraft()`. Base inputs, mode buttons, override inputs, per-row Reset, and Clear overrides already mutate the same `state.draft` and invoke the refresh flow. Theme-list/active-theme updates arrive through `persephone.onThemeChange()` and `scheduleExternalRefresh()`; this refresh deliberately preserves the current draft.
- `renameTheme()` and `deleteTheme()` currently only open `renameDialog` / `deleteDialog`. The dialog `close` handlers then call `persephone.themes.rename()` or `.delete()` and refresh editor state. The AiVision methods must call immediate core operations directly; they must not open or await those dialogs. Keep the dialogs for interactive UI and have their confirmed handlers share the same core operations.
- The Theme Editor manifest already declares `permissions.themes: true`, keeps `appScripting: false`, and sets `minBridgeVersion: "1.35.0"`. The AiVision authoring guide says Persephone inlines `persephone.aiVision` into board frames and exposes a model with `persephone.aiVision.expose(root)`. The boards guide says `appScripting: true` is required for `persephone.call()`, a separate route. Publishing this model does not use `persephone.call()` and needs no additional manifest permission or bridge version beyond BT-034's declarations. Do not install or vendor `ai-vision` in the board.
- The AiVision contract is documented in `C:/projects/persephone/assets/guides/agents/ai-vision.md`; the consumer surface is in `C:/projects/persephone/assets/guides/agents/boards.md` under “A board's own model: `.app`”. The `chess/app.js` model demonstrates a guarded `P && P.aiVision` check, explicit member allow-list, method signatures, cautions, dynamic getters, `summarize()`, and `expose()`. Force Graph builds a separate model (`graph-aivision.js`) from `app.js`; `graph-actions.js` keeps dialog-backed interactive methods and invokes corresponding `*Core` methods after confirmation, while the AiVision surface calls the cores directly. Follow the no-dialog core split, adapting its semantics to Theme Editor.
- **Generator surface additions planned by BT-036:** add `randomize({ blocks?, seed? })`, `setLock(block, locked)`, and `setView("generator" | "details")`. Legal blocks are `background`, `text`, `accent`, `link`, `error`, `warning`, and `success`; reject unknown names with an error listing those values. Randomization uses the UI's locked-block behavior, mutates the shared draft and refreshes through the coalesced `queueDraftRefresh()` path, and returns the contrast-based pass/fallback result. `seed` remains optional. `setView()` changes only the visible tab. Do not expose board-side color or contrast derivation algorithms.
- The guide requires readable validation errors that list legal values, member cautions for immediate/destructive writes, and a synchronous, inexpensive descriptor shape. Property reads and method calls can be asynchronous. `refresh()` is for changes to a collection's empty/non-empty indexed shape; this model has no such collection shape dependency, so do not refresh on ordinary color/name edits. Expose once after the DOM is wired, from the main view, and guard standalone operation when the shim is absent.
- Source mapping verified from `boards/theme-editor/index.html`: stable controls include `source-theme`, `theme-name`, `save-theme`, `save-theme-as`, `revert-theme`, `apply-theme`, `rename-theme`, `delete-theme`, `clear-overrides`, and `theme-polarity`. The current UI's `renameDialog` and `deleteDialog` require human confirmation. The API contract already recorded in BT-034 supplies `list`, `file`, `fork`, `derive`, `contrast`, `save`, `rename`, `delete`, `apply`, `preview`, and `endPreview`; do not add bridge methods or duplicate color/contrast algorithms.

## Implementation Plan

- [x] **Add and publish the model in `boards/theme-editor/app.js`.** After `initialize()` has created the controls and wired event handlers, create a guarded descriptor object and call `persephone.aiVision.expose(model)` once. Use a stable kind such as `ThemeEditor`. Provide a helpful `summary`, concise `overview`, long-form `help`, explicit `members`, and a compact `summarize()` result. Keep all exposed values JSON-safe.
- [x] **Expose live read properties backed by existing state.** Include `draft` as a cloned snapshot containing `id` when present plus `schemaVersion`, `name`, `base`, `isDark`, and `overrides`; `sourceId`, `sourceKind` (`"new" | "builtin" | "custom"`), `themes` (id/name/custom-or-built-in summaries), `derived`, `contrast`, `busy`, `dirty`, `valid`, `validationError`, and `previewStatus` (including superseded state). Read `contrast` from the last authoritative bridge report; do not compute ratios in the board. `summarize()` should report the source, draft name/mode, dirty/valid/busy/preview state, and override count without duplicating the full draft or palette.
- [x] **Expose validated draft-edit methods that use the UI's existing refresh path.** Recommended signatures: `setBaseColor(key: string, value: string | null)`, `setMode(mode: "auto" | "dark" | "light")`, `setOverride(key: string, value: string | null)`, `resetOverride(key: string)`, and `clearOverrides()`. Legal base keys are `background`, `text`, `accent`, `link`, `error`, `warning`, and `success`; the first three are required, while `null`/empty removes only an optional key. Legal mode values are exactly `"auto"`, `"dark"`, and `"light"`, mapped to `isDark: null`, `true`, and `false`. Legal override keys are the 77 CSS variable names and seven `monaco:<key>` names already rendered from `GROUPS` and `MONACO_KEYS`; values must pass the same `CSS.supports("color", value)` check used by the UI. For an unknown key or mode, throw a readable error that includes the allowed values. Each accepted write updates the visible controls/palette, dirty indicator, derived colors, contrast, and valid live preview through the existing `queueDraftRefresh()` pipeline.
- [x] **Expose source and draft lifecycle methods.** `loadSource(themeId: string)` selects a listed theme or `"__new__"` and updates the visible Start from selector; document that it discards the current draft. Unknown ids must throw an error listing the currently legal ids and `"__new__"`. `revert()` calls the existing reversion behavior, restoring a custom draft from `file(id)` or a built-in from `fork(id)`. `applySource()` applies the selected source using the existing bridge method. Ensure all successful state changes re-render the controls so a user sees agent actions immediately.
- [x] **Expose persistence methods and safe dialog-free management cores.** `save()` and `saveAs()` reuse `saveDraft(false/true)`, including current behavior of persisting with `themes.save()` and applying the saved id so the live preview is committed. They validate the current draft first. `renameThemeCore(name: string)` validates that the selected source is a saved custom theme and the trimmed name is non-empty, then uses the existing `themes.rename(id, name)` flow and refreshes the draft/list. `deleteThemeCore()` validates the selected source is a saved custom theme and immediately performs the existing preview ownership check, `themes.delete(id)`, refresh, and new-draft transition. Keep `renameTheme()` / `deleteTheme()` as interactive dialog entry points; after user confirmation, route their close handlers through the same core operations. Include cautions stating that save/save-as writes a theme file and changes the active appearance, rename writes the saved theme, and delete removes a saved custom theme immediately with no agent-side confirmation or undo.
- [x] **Keep UI and agent state coherent.** Make both UI event handlers and model methods call shared mutation/core helpers; do not maintain a separate agent draft. Model getters must always read current `state`, so user keystrokes and mode/override clicks appear on the next read. Successful model writes update corresponding input values and call `renderEditorFields()` / `renderPaletteValues()` and `renderDirty()` as appropriate, then await/coalesce `queueDraftRefresh()` so a subsequent read observes the latest derived/contrast/preview state. Preserve the current `onThemeChange()` rule: update theme choices and active-theme status without replacing a dirty draft. Do not call `remote.refresh()` for each draft mutation; the guide reserves it for indexed collection shape changes.
- [x] **Define invalid and busy behavior.** Invalid/incomplete drafts remain readable and visible, with `valid: false` and `validationError`; edits that make a value syntactically invalid do not replace the last valid preview, matching `queueDraftRefresh()`. `save`, `saveAs`, and `applySource` reject with that validation error when invalid. A source switch or revert may explicitly replace an invalid draft, as the interactive UI permits. Agent mutations that would race a save/load/delete operation must reject promptly with a readable busy error (or be safely serialized); do not leave a remote call waiting on a user dialog. Keep existing operation/generation guards and preview coalescing effective for agent-triggered changes.
- [x] **Add member-level discovery and cautions.** Make each method summary describe whether it changes the live preview, writes persistent theme data, applies appearance, discards the current draft, or deletes immediately. `help` must explain custom vs built-in source behavior, Auto mode (`isDark: null`), optional base-field removal, override reset semantics, CSS color syntax validation, invalid draft behavior, busy state, and that the model edits the user's open board draft rather than a separate `app.themes` object.
- [x] **Add curated controls with `aiVision.createElements()` if the existing selectors support them.** Declare stable names from `index.html` (at minimum source selector, base/mode controls, clear overrides, save/save-as/revert/apply, rename/delete) with useful `purpose` and `where`; include generated element members and `elements`/`provide` on the model. Since all these controls are in the main frame, register the same declarations there only. Do not invent selectors for dynamically generated palette rows; use the existing `data-name` attributes and stable reset names.

## Concerns / Open Questions

- **Deletion and in-board confirmation:** the agent-callable delete must be immediate to satisfy the no-dialog rule. Its `caution` must state the exact effect; the interactive UI keeps its existing confirmation dialog.
- **Draft switching can lose work:** `loadSource()` currently changes the draft. Document this clearly and consider returning a compact before/after source summary so the agent can report what it switched from and to. There is no verified bridge confirmation mechanism to add here.
- **Operation races:** preview is debounced and chained, while source/save/delete operations are asynchronous and guarded with `operation` / `previewGeneration`. The implementation must define a consistent busy policy so calls cannot commit a stale draft or leave an agent call hung while a human interaction is pending.
- **Contrast/derived snapshots may lag during debounce:** define whether a read returns the most recently completed bridge result, and identify it as such while refresh is in flight. Do not claim that `contrast` is current while `busy` or a scheduled preview refresh is pending.
- **No manifest or bridge change is expected:** AiVision publishing is host-shim functionality; `themes: true` remains the only needed permission. Revisit `minBridgeVersion` only if implementation discovers a specific host feature newer than 1.35.0, and cite that feature rather than guessing.

## Acceptance Criteria

- [ ] A trusted Theme Editor page publishes the model at `pages[pageId].editor.app`; `$help` and `$describe` identify its properties and methods, and `summarize()` gives a compact current state.
- [ ] Reads return the current open draft, source, derived values, contrast report, validation state, busy state, and preview state. UI edits are reflected on subsequent reads without a separate model copy.
- [ ] Agent methods set required/optional base colors, mode, and valid overrides; reset one override; clear all overrides; read contrast; switch starting theme; revert; apply; save; save as; rename; and delete. Their changes are reflected in the editor and valid edits preview in Persephone.
- [ ] Invalid keys/modes/colors produce useful errors listing legal keys/modes or expected CSS color syntax. Invalid/incomplete drafts remain visible and do not replace the last valid preview; persistence/apply methods reject invalid drafts.
- [ ] Agent-facing rename and delete never open or wait on dialogs. Interactive UI rename/delete still use their existing dialogs and share the immediate core operations after confirmation. Delete, save, save-as, rename, apply, and source-switch cautions explain persistence, appearance changes, or draft loss accurately.
- [ ] Busy operations reject promptly or are safely serialized; no model method depends on a human dialog response. Existing preview ownership checks and external theme-change behavior remain intact.
- [ ] The model publishes with the host AiVision shim, guarded for standalone execution. Manifest permissions remain `themes: true` only; `appScripting` stays false and `minBridgeVersion` stays `1.35.0` unless a newer required host feature is evidenced.
- [ ] Verify through Persephone MCP by reading `.app.$help` and `.app.$describe`, reading the draft, changing one base/mode/override value, reading contrast, resetting/clearing, switching source, and exercising save/save-as/rename/delete on suitable test themes. Confirm the live editor reflects changes and inspect `ui.log` for errors.
