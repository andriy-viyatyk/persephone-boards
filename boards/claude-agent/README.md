# Agent Chat

Agent Chat provides the `agent.session` v1 service and a local chat page backed by your installed Claude CLI or Codex app-server. Its board id and folder remain `claude-agent`. The service routes v1 sessions through provider adapters: `open.provider` is optional and defaults to `claude`, while descriptions advertise provider identity and capability-gated features alongside the permanent v1 feature set. The page consumes those capabilities and typed session status events without relying on vendor identifiers. Provider selection, session identity, and capability/status additions remain additive fields in contract v1.

## Voice input

When a trusted Speech to Text provider is available, use the microphone button beside the message box to record, then stop to transcribe. The recognized text is inserted into the message box at the caret and is never sent automatically. If several transcription providers are installed, choose one with the provider button. Open the Speech to Text board and finish its setup if Agent Chat reports that the provider is not ready.

Agent Chat needs microphone permission for voice input. After updating an installed trusted board, Persephone shows a **Board permissions changed** prompt listing the new microphone grant. Accept the prompt to use voice input; closing it unregisters the board.

## Codex engine

Use the **Engine** chip on a new-session view to select Claude or Codex. Model choices are grouped by engine, and the selected provider is saved with the restorable page session. Saved sessions retain their owning provider for listing, history, rename, delete, and resume. Codex requires Codex CLI 0.163.0 and runs one `codex app-server --stdio` process per live session. It uses Codex's stored threads for history and resume and exposes model, effort, permission, token, and context controls. Transcript following, cost, rate limits, slash commands, MCP management, and subagent panels remain capability-gated and unavailable for Codex.

The Instructions editor uses separate files for each provider: `%LOCALAPPDATA%\Persephone\board-data\claude-agent\instructions.md` remains Claude's existing file, and Codex uses the sibling `instructions-codex.md` file. Claude's default instructions and composed prompt remain unchanged.

## Group chats

Choose **+ Invite agent** from any chat, including a new or history-only chat, then choose a profile to invite it in one click. **Edit agents…** opens the service-backed profile editor, where each agent has a collapsible panel; expand several to edit them together. Profiles can be created, duplicated, renamed, edited, deleted, or reset to the four shipped defaults: Nova (Reviewer), Rex (Critic), Atlas (Researcher), and Kai (Developer, allowed to edit files; commands need approval). Provider, model, effort, permission preset, and message color are stored with each profile. Claude's Opus, Sonnet, and Haiku aliases remain available; Codex profiles require an exact model offered by the current Codex app-server. Write-capable permission presets show a shared-working-folder warning.

Each invited agent keeps a separate native session and receives the visible group timeline; tool activity stays in that agent's own transcript. User messages, the main agent's final replies, and explicit `post_message` posts are shared with author badges. A joined agent that ends a turn without posting has its final reply posted for it (except the `[[pass]]` marker), and an exact repeat of its last post is not shared again. Profile details are copied into participant records when invited, so later profile changes do not change existing participants. Ask-capable profiles can request approval in the main chat under their author badge; read-only profiles continue to have uncertain actions denied.

The sidebar uses a service-owned group index to nest participant sessions beneath their parent chat, including after a restart before any group chat is opened. Participant history opens read-only and follows live events only when both the parent and participant sessions are already live. To remove a participant while its parent chat is live, click its name in a message header and choose **Remove from chat**, or right-click it in the sidebar; removed participants remain available as history entries. The parent uses a group glyph colored for its main provider. Use **Stop all** to interrupt the main and invited sessions without deleting their saved transcripts. Profile and participant data is stored under `%LOCALAPPDATA%\Persephone\board-data\claude-agent\group-chat\`; no bearer token is persisted. Closing or reloading the board stops active processes while saved group membership remains available for the next resume.

Agent Chat publishes its saved profile catalog through AI Vision at `pages[id].editor.app`. Agents can read/index `profiles`, inspect current `providers`, `permissionModes`, and valid `colors`, and call `create(fields)`, `update(id, patch)`, `duplicate(id)`, or `delete(id)`. Profile writes use the existing service validation and store; deletion is immediate. Profile fields include name, role title, instructions, summary, provider, model, effort, permission preset, and color (`red`, `orange`, `yellow`, `green`, `teal`, `blue`, `purple`, `pink`, or empty for none). Joined-agent message colors apply to existing main-chat history and follow the current profile color. Permission presets are `read-only` (read-classified tools only), `ask` (approval for non-read actions), `auto-edit` (working-directory file writes without approval, approval for other non-read actions), and `full-auto` (all classified actions allowed). Existing participants retain the profile snapshot captured when invited.

## Requirements and first run

- Install the `claude` command line application and sign in through its normal login flow.
- Open the board, review the SDK download notice, and choose **Accept and download**. It downloads `@anthropic-ai/claude-agent-sdk` 0.3.302 from `registry.npmjs.org`, verifies the pinned SHA-512 digest before extraction, and stores the SDK under `%LOCALAPPDATA%\Persephone\board-data\claude-agent\sdk\0.3.302`. The SDK is not included in this board's files.
- Use of the SDK and CLI is subject to Anthropic's legal agreements (see [Accounts and provider terms](#accounts-and-provider-terms)).
- Choose a working directory (type it, or pick it with the folder button), then type your first message to start a session.

## Accounts and provider terms

Agent Chat runs the Claude Code and Codex command line applications installed on your computer. Each engine signs in through its own login (`/login` in Claude Code), and usage is billed to your own subscription or API account. The board never reads, stores, or handles your credentials or session tokens, and it does not offer a sign-in of its own.

- Use only accounts you are authorized to use, and follow each provider's terms. For Claude, see Anthropic's [legal and compliance page](https://code.claude.com/docs/en/legal-and-compliance).
- Do not share your login with other people, and do not offer Agent Chat to others as a service that runs on your account.
- Several agents working at once use up plan limits faster. Subscription limits assume ordinary, individual use; for heavy or shared automation, use API billing.

To use API billing with Claude, configure it in Claude Code itself: sign in with `/login` and choose an Anthropic Console account, set `apiKeyHelper` in your Claude Code settings, or configure a supported cloud provider. The board removes the `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` environment variables before it launches Claude, so a key left in your environment does not silently replace your subscription login.

## Chat page

The left sidebar lists your recent sessions from both engines as a two-level tree: each working folder is a collapsible node, folders are ordered by their most recent session, and sessions inside a folder are newest first. Hover a folder and click **+** to start a new session there. The New session form asks only for a working directory, and not even that when you start it from a folder's **+** (or `/clear`). A new session is named after the first few words of its first message (or the date and time, if it starts with a command); the name is saved as the session's title after its first reply. Under the message box, three chips show the session's permission mode, model, and effort; click one to pick another. The mode chip offers the terminal's **Auto** (the default for every new chat: a classifier approves safe actions and asks about the rest), **Bypass** (every tool runs without asking), and **Plan** (Claude researches and proposes a plan without changing anything). In Auto, a call the classifier cannot decide shows an approval card in the chat with **Allow**, **Allow for this session**, and **Deny**. In Plan, the finished plan shows as a card with **Approve, continue in Auto**, **Approve, continue in Bypass**, and **Keep planning** (Claude then asks what to change). A mode change applies to a running session at once, even mid-turn, as Shift+Tab does in the terminal, and a resumed session continues in the mode it last ran in. A card left unanswered when the turn ends or is interrupted no longer applies. A new session starts with the board's default model and effort settings, else the ones Claude Code itself would use (`model` and `effortLevel` from your user settings and the folder's project and local settings), else Opus at medium effort. For a running session the chips show what it runs with, and a change applies from the next turn, between turns only, like the terminal: a model change notes that the next turn reads the whole conversation again without the prompt cache, and an effort change runs `/effort <level>` in the chat, which applies to that session only. A choice made on a session that is not running applies when you resume it. Right-click a session for **Rename** (saved as the session's custom title in its transcript) or **Delete** (after a confirmation, removes its transcript from disk; an open session is closed first). Drag the sidebar's right edge to resize it (double-click resets); the width is remembered. On load only the most recent folder is expanded. Selecting one replays its stored conversation and keeps following it, so turns written by another process (Claude Code in a terminal, for example) appear as they happen; the board resumes the session with its engine process only when you send a message from it or click **Connect**. While the message box is empty on a session the board is not running, the **Send** button reads **Connect**: it resumes the session without sending anything, and the chips then show the model and context fill it actually runs with. Right-clicking a session that is not running offers the same **Connect**. The list itself refreshes when stored transcripts change; the refresh button in the page toolbar reloads it at once. The page reopens the selected session after a reload, an app restart, or a move to another window; **New session** in the page toolbar returns to the start form. The toolbar also shows the open session's folder, an **Instructions** button, and, during a reply, **Interrupt**. **Instructions** opens an editor for the provider instructions added to Claude's system prompt: the board ships a default, your saved text replaces it (stored in `%LOCALAPPDATA%\Persephone\board-data\claude-agent\instructions.md`), and **Reset to default** restores the board's text. Saved changes apply to sessions started or reopened afterwards; a connected session keeps the instructions it started with. Your messages appear on the right and the agent's replies on the left, rendered as Markdown (sanitized; raw HTML is not trusted). Tool calls, thinking, and notices appear as collapsible lines between messages. A finished background task (a shell command or subagent run in the background) shows as one **Task** line with its summary, as in the terminal; expand it to see the full notification. Hover a message to show its **Copy** and **Open in a new page** buttons on its top edge: Copy puts the message on the clipboard as plain text (the Markdown source) and as formatted HTML, so it pastes with formatting into apps such as Teams; Open shows the message in a new Persephone Markdown view page. The message box grows with its text; Enter adds a new line and Ctrl+Enter sends.

### Several sessions at once

The board can run several sessions side by side, like terminal tabs. A session you send a message to (or open a panel for) runs on the board with its engine process, and it keeps running when you click another session: a reply in progress continues, and its turns are there when you come back. Each session keeps its own transcript, scroll position, unsent message, status line, and footer values. An engine icon before each session name (Claude or Codex) shows its state in the engine's color: muted when the board does not run it, bright with a green dot on its left edge when it does, pulsing while the agent works. A collapsed folder shows a green dot when one of its sessions is running, and a session that finished a reply while you were looking at another one has a bold title until you open it. Right-click a running session and choose **Disconnect** to end its process; its icon then turns muted, and selecting it again replays its stored conversation. **New session** and **+** leave running sessions running. Running sessions end when the page is closed or reloaded; the page then reopens only the session it was showing, without running it.

### Slash commands

Type `/` at the start of the message box to list the session's commands: skills, plugin and custom commands, and Claude Code's built-in ones. Arrow keys move through the list, Tab completes the name, and Enter runs a command that takes no arguments (or completes one that does). The list comes from the live session and is cached for the next time the board is not connected. Most commands are sent as a message, exactly as typed, and run the way they do in the terminal: `/compact` shows a "Conversation compacted" line with the token counts and a collapsed summary, and commands that print output (`/usage`, `/context <args>`, `/effort <level>`, and others) show it in a box under the command. `/model <name>` and `/effort <level>` typed with an argument also update the footer.

The terminal draws its own screens for a few commands; the SDK has none, so the board handles these itself (marked **board** in the list):

- `/mcp` lists the session's MCP servers with their state, scope, transport, and tools, with **Reconnect**, **Disable**/**Enable**, and **Authenticate** for servers that need sign-in (it opens the sign-in page; press **Reconnect** afterwards). The panel refreshes itself while open, since claude.ai connectors appear a few seconds after the session starts.
- `/model` and `/effort` with no argument open the model and effort chips' menus.
- `/context` shows what fills the context window as a stacked bar and a table by category, with the auto-compaction threshold and the memory files and MCP tools that use tokens.
- `/clear` returns to the start form with the same folder, engine, model, and effort, ready for a new session, and deletes the session you leave (its process is ended and its transcript removed from disk), as the terminal leaves it behind.
- `/rename` with no argument opens the rename dialog.

These panels need a session the board runs: on a selected session that the board is only following, they resume it first, as sending a message does. A stored session's history shows its commands, compaction, and the summary it continues from; the output of local commands such as `/usage` is not part of the stored history the SDK returns, so it appears only live.

The context fill shows at the right under the message box (click it for the `/context` breakdown). Persephone's footer bar shows your plan's 5-hour and 7-day usage-limit percentages (hover for reset times), and the last turn's tokens and cost with the session's running total. Context and limit values turn highlighted at 70% and red at 90%. Values appear once Claude reports them, usually after the first reply.

The installed SDK file is hash-checked each time it loads. A missing or modified file returns the board to the consent and download flow. Discovery (`describe`) remains available without the SDK; listing or opening sessions requires it.

The sidebar also shows an **Agents** tree for the selected session when it has spawned subagents. The main session is the root; its subagents appear as flat children with their description and agent type. Select a child to read its transcript, or select the root / **Back to main chat** to return. Agent/Task tool-call rows also open the matching child. A pulsing green dot marks an agent that is still unfinished and active or recently updated; a neutral dot marks a completed or stale agent. Only running agents are listed by default; **Show N more** reveals the inactive ones used in the last 24 hours (older ones are not listed, though their tool-call rows still open them) and **Hide N inactive** folds them away again. An inactive agent you are reading stays listed until you switch to another chat. Subagent transcripts are read-only: the main session's status, footer, and Interrupt control remain available, while message entry and slash commands are hidden.

## Permissions and network behavior

The board asks for `service` and `appScripting`. `service` runs its resident Node process and launches the installed CLI with your account privileges. `appScripting` is required to issue an optional private Persephone MCP endpoint; that endpoint gives the associated Claude session full control of Persephone. Each session gets its own endpoint, and it is revoked when the session ends. Sessions started from this board's own chat page are unrestricted by the contract and use Claude Code's own permission mode, picked with the mode chip: a new chat starts in **Auto**, which asks in the chat about what its classifier cannot decide, as **Plan** does for its plan; in **Bypass** Claude edits files, runs commands, and uses Persephone without asking. Sessions opened by other boards through the `agent.session` contract use the contract's permission modes instead. Cross-board calls are clamped by the configured permission ceiling, which defaults to `read-only`.

Manifest `network` stays disabled. The board's Node module service downloads the pinned SDK directly from npm only after consent; that Node process can access the network independently of bridge networking. The board never reads CLI credential files or handles login tokens. It relies on the unmodified installed CLI and its existing login.

Configure the executable override, model, effort, and the cross-board ceiling in **Settings → Editors → Agent Chat**; edit provider instructions in the toolbar's **Configure** dialog (Instructions tab; the Agent profiles tab is the profile editor). The service reads these itself; consumer boards' messages cannot replace the provider instructions or the ceiling.

## Privacy

Prompts, working-directory content, and tool activity are handled by the installed CLI as part of its normal operation. The board sends bounded event summaries to a connected consumer and never sends file contents in `file-change` events. SDK files are kept in user data and are not written into or shipped with the board.
