## Status

## Goal

Create a `Claude Agent` board that runs the user's installed `claude` CLI through the Claude Agent SDK and provides the vendor-neutral `agent.session` v1 service, plus a single-agent chat page using that same protocol. Preserve the user's CLI login without reading credential files, and enforce the contract's caller permission ceiling and session lifecycle.

## Background

- This is Phase 1 of Persephone [EPIC-131](../../../../persephone/doc/epics/EPIC-131.md), specifically US-1706. The epic settles on the TypeScript Agent SDK, `pathToClaudeCodeExecutable` for the installed CLI, the SDK `query()` streaming API, `claude_code` preset plus appended instructions, explicit `permissionMode`, `canUseTool`, retained `settingSources`, a private session MCP endpoint, and Windows process-tree cleanup.
- The normative contract is [Agent Session v1](../../../../persephone/assets/guides/agents/agent-session.md). Its exact interface id/version is `agent.session`/1. Each channel is one live session; `open` and `session-started` carry `contractVersion: 1`; closing a channel stops the process tree and revokes its MCP endpoint while preserving the CLI's stored session.
- The live [Boards guide](../../../../persephone/assets/guides/boards.md) and Persephone source confirm bridge `1.42.0` is needed for module-service channels, service interfaces, multiline settings, and `persephone.mcp.issueSessionEndpoint()`. Endpoint issuance requires `appScripting`; service channels have a 1 MiB message cap, 256 unacknowledged messages per direction, a maximum of 16 channels per frame and 128 per service. Service senders must honor `writable`/`whenWritable()` and keep contract events under 900 KiB.
- Runtime facts verified in `assets/module-service-host.mjs`, `src/main/module-service-supervisor.ts`, `src/main/module-service-record.ts`, `src/main/mcp/private-session-endpoints.ts`, and `src/board-shim.ts` in the Persephone repo:
  - The service environment is an allowlist. `Path`/`PATH`, `USERPROFILE`, `APPDATA`, and `LOCALAPPDATA` are included; `HOME`, `CLAUDE_CONFIG_DIR`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, and other unlisted variables are not. Windows Claude config/login can use `USERPROFILE`/`APPDATA`; if non-Windows hosting is in scope, verify the CLI's home/config resolution because the host does not pass `HOME` or `CLAUDE_CONFIG_DIR`.
  - The SDK's `env` option replaces the child environment. Construct the child environment from the service's `process.env` and explicitly remove both `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` as defense in depth; the supervisor allowlist already omits them.
  - The current service host exposes `persephone.service.onChannel()`, `onShutdown()`, `persephone.mcp.issueSessionEndpoint()`, and board-scoped key-value `persephone.storage`, but no settings API. Persephone US-1711 adds `persephone.settings.get(id)` and `persephone.settings.onChange(cb)` to the module-service host with the page shim's board-scoped, effective-value semantics, in the unreleased bridge 1.42.0 / app 5.0.13. This board depends on US-1711 and needs no new bridge or app minimum.
  - The supervisor waits `SERVICE_SHUTDOWN_TIMEOUT_MS` (2 seconds per the Persephone runtime configuration) after sending shutdown, then kills the utility process. On Windows its helper uses `taskkill /PID <pid> /T /F`; the board must stop each Claude child tree inside the service's two-second callback window.
  - `issueSessionEndpoint()` returns `{ url, headers, token, revoke() }`; the host's revoke operation invalidates that token and any HTTP MCP sessions it owns. The service host also revokes active handles on shutdown.
- The current development Persephone reports version **5.0.13**. Set `minAppVersion: "5.0.13"` and `minBridgeVersion: "1.42.0"` for this first implementation.
- `@anthropic-ai/claude-agent-sdk@0.3.302` is not bundled or shipped in the board ZIP. Per the verified package inspection supplied for this review, `package/sdk.mjs` is a self-contained 1,290,292-byte ESM file whose imports are Node built-ins, with no relative `core-*.mjs` chunks or runtime `zod`/peer imports. On explicit user consent, the board downloads the pinned npm tarball (`https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/-/claude-agent-sdk-0.3.302.tgz`, SRI `sha512-VUxgraOIxnu4COhS9IkP3AF21kh9KOOF8oyU7pc6q0PfzMPlarbnhXvuhCNIPPYddhIev+17LLq1nZ700GdLBg==`), validates integrity before extraction, and stores only `package/sdk.mjs`, `package/LICENSE.md`, and `package/package.json` in a versioned user-data directory. `npm pack` could not be repeated in this environment because npm is configured offline; the plan uses the package facts supplied and verified by the user.
- The SDK package `LICENSE.md` says © Anthropic PBC, all rights reserved, and subjects use to Anthropic's legal agreements. No Anthropic code is distributed in the board ZIP; the per-user consent card and board README disclose the download and terms. The EPIC's separate terms concern about third-party Claude.ai login/rate-limit products remains relevant: use the user's own unmodified installed CLI and login, never read, copy, log, or otherwise handle CLI credential files or session tokens, and use the display name **Claude Agent** (not “Claude Code”).

Reserve `cli-not-found` for a missing installed CLI executable. The UI's consent acceptance starts download; tampered/invalid files are removed and consent/download is offered again.
- [ ] Validate open request model, effort, cwd, resume id, limits, and permission mode. Determine `crossBoard = Boolean(info.interface && info.caller)`. For cross-board calls clamp requested permission mode down to the configured cross-board ceiling and report the effective mode; same-board chat is not clamped by that setting. Never raise above either the request or ceiling. Reject unknown contract versions or malformed requests with `protocol-error`.
- [x] Launch/resume with SDK `query()` using streaming-input mode for a long-lived chat and resume: `sessionId` when requested. Always set `permissionMode` explicitly. Map contract modes to the native modes in the normative table: read-only and ask use `default`, auto-edit uses `acceptEdits`, and full-auto uses `bypassPermissions`. Register a `hooks.PreToolUse` callback for every mode. It runs before permission rules and can deny even in `bypassPermissions`; its `hookSpecificOutput.permissionDecision` is `deny`, `ask`, or `allow`. Use `deny` for actions forbidden by the effective contract mode/ceiling, `ask` to pass eligible actions to `canUseTool`, and `allow` only where the effective mode authorizes the action. `canUseTool` alone is insufficient because settings allow rules and mode grants can auto-allow tools before that callback. Report the effective contract mode; native Windows lacks Claude sandbox support and mappings are best-effort.
- [x] Use `systemPrompt: { type: "preset", preset: "claude_code", append: composedInstructions }`; do not replace the preset or use `--bare`. Set `settingSources: ["user", "project", "local"]` explicitly: the pinned SDK defaults to loading no filesystem settings when omitted, and project is required for `CLAUDE.md`. These sources can contain `permissions.allow` entries, so the PreToolUse gate below must override auto-allowed actions. Build `composedInstructions` as exactly: (1) short provider environment preamble (Persephone, board name, cwd, whether private MCP is attached, chat UI), (2) provider's `main-instructions` setting, (3) caller's `open.instructions` if present. Emit the actual composition as `session-started.instructions.composed`. Instructions are fixed for the live session; resumed sessions do not promise that changed append text takes effect.
- [ ] Set SDK `includePartialMessages: true` and `spawnClaudeCodeProcess`. The callback itself spawns the resolved installed executable using `child_process.spawn(command, args, { cwd, env, stdio: "pipe", windowsHide: true })`, retains the child process/PID per session, and returns the pinned declaration's exact `SpawnedProcess` shape. Keep tool/input summaries at or below 16 KiB UTF-8, text/summary/detail/title fields at or below 32 KiB UTF-8, each serialized service-to-page event at or below 900 KiB, set truncated: true when truncating, and never send file contents in file-change.

### Mapping: SDK messages to `agent.session` v1

Use the contract's native mapping as the implementation checklist; field names below are contract event fields. Extract only bounded summaries, never arbitrary full tool input or file content.

| Native Claude SDK message/event | Contract output |
|---|---|
| `query()` start/resume; SDK init `system` message (`subtype: "init"`, session id) | On successful open, emit `session-started` with `sessionId`, selected `model`, effective `permissionMode`, applied `limits`, `instructions: { composed }`, and `contractVersion: 1` before turn events. |
| `SDKResultMessage` / result subtype marking turn lifecycle | `turn-started` once for each accepted `send`; `turn-ended` once with `reason` (`completed`, `interrupted`, `limit`, or `error`) and available `usage`. |
| `stream_event` `content_block_delta` with `delta.type: "text_delta"` | `text-delta` with `text`; final assistant/result text also becomes `text` where supplied. |
| Thinking content blocks / SDK thinking messages when enabled and exposed | `thinking-delta` with `text`; omit if unavailable. |
| Assistant `tool_use` blocks; stream `content_block_start`/`input_json_delta`; SDK tool-progress messages | `tool-call` with `callId`, `name`, bounded `input` summary. |
| User `tool_result`, `SDKToolProgressMessage`, `SDKToolUseSummaryMessage` | `tool-result` with `callId`, `ok`, bounded `summary`. |
| Edit/Write tool calls/results and `SDKFilesPersistedEvent` | `file-change` with normalized `path` and `kind`; no file contents. |
| `options.canUseTool(toolName, input, { signal, suggestions, ... })` | For eligible actions, send `approval-request` (`requestId`, `kind`, `summary`, `detail`), keep callback pending until `approval-response`, then allow/deny the callback. |
| SDK `options.hooks.PreToolUse` callback, receiving typed hook input and returning `hookSpecificOutput.permissionDecision` (`allow`, `deny`, or `ask`) | Mandatory policy gate before native permission/settings rules in every mode, including `bypassPermissions`: classify every tool. Candidate read-only names are `Read`, `Glob`, `Grep`, `LS`, `WebSearch`, and `WebFetch` (verify the pinned SDK's actual names); treat `Edit`, `Write`, `NotebookEdit`, `MultiEdit`, `Bash`, PowerShell, every `mcp__*` tool, and unknown tools as side-effecting. Allow only the read-only class in read-only, deny side effects forbidden by the effective contract mode/ceiling, and return `ask` for actions requiring approval in `ask`/`auto-edit`; the SDK then routes the ask through `canUseTool` and contract approval flow. A hook denial still blocks in bypass mode. Confirm the pinned package's exact declarations and behavior before implementation. |
| `Query.interrupt()` / interrupted result | `turn-ended` with `reason: "interrupted"`. |
| `SDKResultMessage` usage and estimated `total_cost_usd` | `turn-ended.usage` with available `inputTokens`, `outputTokens`, optional `cachedTokens`, and optional estimated `costUsd`; omit unavailable values. |
| SDK error/result, `system/api_retry`, rate-limit and status messages | Use applicable contract `error` codes (`cli-not-found`, `cli-version-unsupported`, `not-logged-in`, `model-unavailable`, `resume-not-found`, `limit-reached`, `busy`, `protocol-error`) or a non-fatal `notice`; fatal errors end the session. |
| Other SDK messages, including `SDKUserMessageReplay`, `SDKCompactBoundaryMessage`, local command output, hook/plugin/task/session-state/notification/elicitation messages, and future union members | No one-to-one v1 event is defined. Ignore safely or reduce to a useful bounded `notice`; do not expose unsupported native shapes as protocol events. |
