# BT-084: Text to Speech board — play through the audio service; `speak` / `stop`

## Goal

Update the Text to Speech board so it synthesizes locally and plays through Persephone's `audio@1` capability. Publish agent-callable `speak(text, { lang?, voice?, speed? })` and `stop()` methods that return `finished` or `interrupted`, following EPIC-139 decision 7.

## Background

- **Current board (verified in `boards/text-to-speech/`):** `board-manifest.json` is version `1.0.0`, requires Persephone `5.0.18` and bridge `1.42.0`, declares the legacy `speech.synthesize@1` service interface, and requests the service permission. `scripts/service.mjs` validates `describe` and `speak` channels, queues synthesis FIFO, and returns chunked `pcm-f32le` audio plus `done`/`error`. `scripts/engine.mjs` loads Supertonic 3 int8 through sherpa-onnx; it is configured for two threads and returns audio at 44.1 kHz. `scripts/text.mjs` splits input by sentence and long sentences at commas. `scripts/downloads.mjs` manages explicit Windows x64 runtime/model install and verifies pinned assets.
- **Current page UI (verified in `index.html` and `app.js`):** the page owns an `AudioContext`, converts received float PCM chunks into Web Audio buffers, and schedules playback. Its Install/cancel/delete UI and English/Ukrainian test samples remain useful; route Speak and Stop through the revised service so the test exercises the same `audio.play` path as callers. Remove page-side PCM conversion, scheduling and `AudioContext` ownership.
- **Current docs (verified):** `CLAUDE.md` describes the old channel-based contract and page playback; `README.md` documents local Supertonic, install, licensing and Windows x64 support; `WHATS-NEW.md` currently ends at `1.0.0`. `doc/tasks/BT-082-text-to-speech/README.md` records the original implementation and checks. Keep install, model, licensing and offline details while replacing obsolete playback/contract descriptions.
- **EPIC-139 decisions 2, 5, 6, 7, 10 and 11** (read in `C:/projects/persephone/doc/epics/EPIC-139.md`): retain Supertonic 3; Persephone owns playback via the hidden audio window; boards use the unified capability registry; `speak` resolves `{ status: "finished" | "interrupted" }`, `stop` stops all current speech, missing language defaults to Ukrainian for text containing Cyrillic and English otherwise, and input has no length limit; voice instructions live in the user's files; playback/capture share the platform audio window and echo-cancellation path.
- **Audio service contract** (verified in `C:/projects/persephone/assets/guides/agents/audio.md` and US-1790): call `persephone.getCapability("audio", { version: 1 })`, then `audio.play({ sampleRate })`. Send `{ type: "chunk", data: ArrayBuffer }`, then `{ type: "end" }`; listen for `{ type: "ended", epoch, status: "finished" | "stopped" }`. `stop` cancels scheduled audio and reports `stopped`; closing also cancels. The queued-audio limit is five seconds, with overflow closing as `channel-backpressure`. Playback accepts mono float32 little-endian at integer rates from 8,000–192,000 Hz and Web Audio resamples it. Channel establishment is limited to 15 seconds. Consumers need `uses: [{ id: "audio", version: 1 }]`, `minBridgeVersion: "1.51.0"`, `minAppVersion: "5.0.18"` or newer; a service consumer needs `permissions.service: true`. Playback needs no microphone permission.
- **Capability contract** (verified in `capabilities.md` and `boards.md`): board-provided `call` methods are declared under manifest `capabilities` and implemented in the service with `persephone.capabilities.handle(id, method, handler)`. Agent visibility defaults on; declarations have method timeouts. `getCapability` requires bridge 1.51.0. Calls support JSON arguments/results and an `AbortSignal`; `stop` can be a normal call. Audio is a channel method and cannot be called by an agent. `boards.md` already points to the capability contract, and `capabilities.md` documents `getCapability`, `uses`, declarations and the audio guide; update those cross-references only if implementation reveals a concrete missing instruction.
- **Repository precedent checked:** `boards/claude-agent/board-manifest.json` declares `uses` for `speech.transcribe`; `boards/speech-to-text/board-manifest.json` declares method-bearing capabilities; `boards/theme-editor/board-manifest.json` declares an `open` capability. `rg` found no `persephone.getCapability()` in board `.js`/`.mjs` source, so there is no existing in-repo consumer implementation to copy. Follow the normative audio and capability guides.
- **Contract guide to revise:** `C:/projects/persephone/assets/guides/agents/speech-synthesize.md` still specifies a PCM-returning `speak` channel and consumer-owned playback. EPIC-139's linked-task table says US-1784's guide is “revised in BT-084”. Replace it with decision 7's contract and document that the board plays through `audio@1`.
- **Legacy declaration evidence:** `module-service-supervisor.ts:174,270,862–896` indexes `serviceInterfaces` for legacy discovery/connect authorization and closes existing interface channels when the declaration disappears. `board-trust-service.ts:458–480` includes normalized interfaces in the service snapshot and merges them into capabilities; the board manifest's trust disclosure lists interfaces (`board-manifest.ts:952–962`). Its `manifestChanged` comparison covers permissions and `uses`, not interfaces alone; adding the audio use can require re-trust. `capability-contract.ts:19–62` merges both declarations by id/version: explicit `speak` overrides the synthesized channel of that name, while legacy `describe` remains a synthesized channel. `boards/speech-to-text/board-manifest.json` uses both forms. Keep the legacy entry and `describe` response for compatibility; reject the obsolete PCM-returning `speak` channel cleanly.

## Implementation Plan

- [x] **Declare the new surface and version.** In `boards/text-to-speech/board-manifest.json`, bump version from `1.0.0` to `1.1.0`; set `minBridgeVersion` to `1.51.0` for `getCapability` and capability handlers; keep `minAppVersion` at `5.0.18`. Keep `permissions.service: true` and the existing `serviceInterfaces` entry, add `uses: [{ "id": "audio", "version": 1 }]`, and add `capabilities: [{ id: "speech.synthesize", version: 1, title: "Text to Speech", methods: { ... } }]`. Declare `speak` as `kind: "call"`, required `text: string`, optional `options: { lang?: string; voice?: number; speed?: number }`, result `{ status: "finished" | "interrupted" }`, `agent: true`, and `timeoutMs: 600000` (`CAPABILITY_MAX_TIMEOUT_MS` in `src/shared/capability-limits.ts`). A single call times out after ten minutes end-to-end, including startup, synthesis and playback; the handler must stop playback on `ctx.signal` abort. Declare `stop` as `kind: "call"`, no arguments, result `null`, `agent: true`, timeout `10000`. The synthesized legacy `describe` channel remains discoverable and returns its description; channels cannot be invoked by agents. Keep existing settings and service declaration.
- [x] **Register and implement calls in `boards/text-to-speech/scripts/service.mjs`.** Register `speak` and `stop` via `persephone.capabilities.handle("speech.synthesize", ...)` synchronously during startup. Keep private page channels and the legacy `describe` response; reject PCM-returning `speak` channel opens cleanly. For both capability handlers, `same-board-only` rejects every capability caller (agents, other boards and Persephone) with `permission-denied`; `accept-granted` accepts granted callers. The own page uses the private channel below. `ctx.caller` supplies caller metadata, but its author-chosen `id` alone is not an authorization identity. Validate text, options, language, numeric voice index (0–9), and finite speed (0.5–2); omitted voice uses the `default-voice` setting, omitted speed is 1. If `lang` is omitted, select `uk` when text contains a Cyrillic code point and `en` otherwise. Impose no board text-length limit. Missing model remains a clear failure; requests never trigger downloads.
- [ ] **Stream each generated sentence to audio with bounded playback.** Keep `splitSentences()` and serialize `generateAsync()` calls; pipeline synthesis of the next sentence while the current audio plays, with a bounded producer buffer. Use the returned sample rate (currently 44,100 Hz) and one `audio.play` channel per `speak`; verify later sentences use the same rate. Register message/close listeners immediately and send copied finite mono float32 little-endian `ArrayBuffer` chunks. Put chunk duration (~0.25–0.5 s) and lead budget (~2 s) in one commented tuning-constants block. Pace with a monotonic wall clock: before sending a chunk, sleep until `sentSeconds + chunkSeconds - (now - firstSendTime)` fits the lead budget; start the clock at the first send. The real playback start lags that send, so the ~3 s remaining under the five-second cap tolerates startup lag; verify this assumption under load. Await `whenWritable()` separately for transport backpressure; handle establishment, close and `channel-backpressure` errors. After the final chunk send `{ type: "end" }` and wait for `ended`; only final `finished` resolves finished, while an intentional stop or replacement resolves interrupted. Unexpected close or stop is an error. Check cancellation throughout, including pacing sleeps.
- [x] **Define interruption and concurrent `speak` behavior.** Use **replace** semantics: a new `speak` interrupts the prior operation and becomes sole active call; `stop()` interrupts all active or pending speech. On `ctx.signal` abort, explicit stop or replacement, send `{ type: "stop" }` on the active play channel (or close it), stop sending, cancel pacing waits and discard any in-flight sherpa result; start no further sentence for the displaced operation. Explicit stop and replacement resolve displaced live calls as `{ status: "interrupted" }`. For a signal-aborted call just return after cleanup: the router rejects it and ignores late settlements. Native inference may not be interruptible; do not wait for it before stopping audio, and keep at most one inference in flight. Prevent stale cleanup from affecting a successor. Coordinate shutdown, install/delete maintenance and idle-unload with actual native work.

## Concerns / Open Questions

- Wall-clock pacing assumes startup lag stays within the safety margin; measure under load. A platform drain acknowledgement is the fallback if this proves unreliable.
- Sherpa inference may not cancel while generating a sentence. Cancellation must stop current playback promptly and suppress the result when inference returns; verify replacement calls do not accumulate an unbounded queue.
- The platform also limits call payload size; no board-imposed length limit removes that transport limit.
