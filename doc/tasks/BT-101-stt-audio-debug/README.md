# BT-101: Speech to Text and Agent Chat — always use cleaned Persephone audio; audio debug panel

## Status

**Status:** Active

**Priority:** High

**Board ids:** `speech-to-text`, `claude-agent`

## Goal

Route both boards' microphone transcription capture through Persephone `audio@1` default processing, which follows the user's microphone cleaning settings. Let the user see and hear the PCM actually accepted by the Speech to Text provider during a selected transcription, including when phone noise degrades recognition; keep the debug recording transient, explicit and bounded.

## Background and verified findings

References to `C:/projects/persephone/` are the host source checkout inspected for this task; line numbers describe its current 5.0.19 tree. This task changes only this repository.

- The provider does **not** capture the input for external callers. `boards/speech-to-text/scripts/service.mjs:679` creates each request; `:729-754` validates incoming `audio` messages and appends their PCM bytes to either the live stream or the record-then-transcribe buffer. The contract is mono PCM s16le at 16 kHz (`:127`, `:923-928`). Live segmentation and Whisper windows are downstream of this boundary, so the incoming bytes are the right common tap, although not every sample necessarily becomes a Whisper inference window.
- The board's own test page currently uses `navigator.mediaDevices.getUserMedia`, selected page-origin microphone ID, mono, echo cancellation and Chromium noise suppression (`boards/speech-to-text/app.js:153-161`, `:204-217`), then resamples, quantizes and sends chunks (`:173-186`, `:292-326`). It does **not** use `audio@1`; its direct microphone bypasses the host audio-service cleaning. Replace that capture path; once migrated, the simplest check is to arm the debug panel and record using the board's own test recorder.
- Agent Chat ordinary dictation currently captures directly with `getUserMedia` and its `agent-capture` worklet (`boards/claude-agent/app.js:2852-2891`); `consumeVoiceSamples`, `recordVoiceLevels`, `checkVoiceAutoStop` and `createVoiceContext` are at `:2738-2799`. Its live requests currently have no sample limit, while record-then-transcribe requests use the provider limit (`:2878-2879`); preserve both behaviors.
- Agent Chat Wake mode already requests default `audio@1` microphone capture with `echoCancel: true` and the saved `wake-device`, after validating it with `audio.devices()` (`boards/claude-agent/wake-assistant.js:221-236`). Its `onChunk` validates and puts those same capture chunks into the ring and active request (`:318-336`); `appendAudio` slices them into request buffers (`:339-358`), the pre-roll is appended from that ring (`:592-594`), and the request sends slices of those buffers as `audio` messages (`:414-427`, `:439-447`). Thus post-wake transcription uses the same default-processed capture, subject to timing/cropping; it is cleaned when the host setting enables cleaning.
- Persephone voice typing passes `microphoneOptions(stream)` to `PcmAudioCapture` (`C:/projects/persephone/src/renderer/ui/voice-typing/VoiceTypingController.ts:210`, `:319-350`). The Monaco-toolbar Transcript passes those options for its microphone and none for computer audio (`C:/projects/persephone/src/renderer/ui/transcript/TranscriptController.ts:132-137`, `:173-222`). Both microphone paths use host cleaning when `microphone.clean` is on; computer audio is not microphone-cleaned. No Persephone host change is needed. These clients reach this board only when they select it as provider; other providers and file calls do not pass through a streamed request here. `transcribeFile` decodes a WAV separately (`boards/speech-to-text/scripts/service.mjs:657-670`, `:891-897`).
- The capture contract in `C:/projects/persephone/assets/guides/agents/audio.md:107-118` is `{ type: "chunk", epoch, timeMs, sampleRate: 16000, data: ArrayBuffer }`, with mono s16le data in 3,200-sample chunks. `boards/wake-word/scripts/service.mjs:306-319`, `:350-361` and `boards/claude-agent/wake-assistant.js:229-236`, `:323-349` consume this shape. `audio.devices()` returns audio-window-origin IDs; page-origin IDs may not work (`audio.md:47-53`).
- `C:/projects/persephone/assets/guides/agents/audio.md:20-67` and `src/main/capability-registry.ts:20-39` define `audio@1`: microphone or computer capture, optional device, echo cancellation and `processing: "default" | "raw"`. Default microphone follows host Microphone Audio settings; it is not a guarantee that cleaning is enabled. Raw disables requested Chromium processing and host cleaning, but OS/hardware processing may remain. The host chooses a per-device notch and settings (`src/renderer/audio/audio-window.ts:81-84`, `:177-185`, `:217-224`); the worker can report neural or notch fallback (`src/renderer/ui/speech/microphone-cleaning-worker.ts:74-77`, `:112-113`). These status messages go to host IPC, not capture subscribers (`audio-window.ts:147-149`); the board cannot report the actual neural/notch/unfiltered status from this API. A capture failure may close the channel.
- A transcription request carries format and optional transcription options, not trustworthy source, device or processing metadata (`service.mjs:679-682`, `:923-928`; `C:/projects/persephone/assets/guides/agents/speech-transcribe.md`). The service cannot infer those facts from samples or caller identity. Label tapped requests **source/device/processing unknown** unless an existing, verified contract supplies them; do not invent status or infer cleaning.
- The lab's lower panel (`C:/projects/persephone/.persephone/boards/audio-filter-lab/index.html:7`, `app.js:96-133`, `spectrogram.js:1-63`) is the visual precedent. Copy/adapt the board-owned FFT and review rendering from `boards/wake-word/spectrogram.js:1-63` and `boards/wake-word/review.js:1-102` into Speech to Text; boards cannot import one another. Their current full-clip rendering is not a live incremental renderer.

## Concerns / Open Questions

- The tap records audio sent to this provider, including from other trusted clients, only after explicit arming; a clear UI must make that scope visible. Concurrent requests require explicit selection and must never be combined. The service cannot name or characterize a source without metadata from the caller. File transcription is outside this streaming tap.
- A running request is observable only from the time the user attaches; no retroactive claim of a complete recording. A stopped/overflowed debug stream is explicitly incomplete. Source changes or dropped samples upstream are not discoverable from PCM alone.
- `audio@1` default processing follows the user's host settings: if microphone cleaning is disabled, or on an older supported host without the newer neural pipeline, the board cannot force or verify neural cleaning. The host can fall back, and the capture contract exposes no cleaning-mode status; show unavailable rather than making a claim. Inform users where the host setting is controlled.
- Device IDs can change or be unavailable; keep Wake and dictation selection behavior consistent and show a default fallback. Startup and backpressure handling must not silently truncate audio.
- Playback can cause microphone feedback if a live capture remains open; make playback and debug capture mutually exclusive. Consider accessible keyboard seeking alongside click seeking.

## Acceptance Criteria

- [ ] An explicitly armed or selected streaming request records the exact accepted PCM interval, with no extra capture; source/device/processing and cleaning status are shown as unknown when unavailable. Multiple simultaneous requests remain separate.
- [ ] A live spectrogram scrolls as audio arrives with a moving waveform or level; rendering and all queues are bounded and do not block or disrupt transcription. At 60 s only the debug tap stops and the user sees why.
- [ ] Play, Stop and click/keyboard seek work, with the diagram cursor and time synchronized to playback; Clear and page close release transient audio, queued data and resources. No debug audio is saved or logged.
- [ ] Both boards use `audio@1` default microphone processing for all their transcription microphone captures, with no direct `getUserMedia` or raw mode. Speech to Text uses `audio.devices()` IDs; Agent Chat dictation uses the same validated saved device as Wake, with a clear fallback. Live/record behavior, sample limits, level and silence auto-stop remain functional.
- [ ] UI and canvas respect `--p-*` themes; all language packs have strings, controls are accessible, and the board works offline without external assets. `ui.log` has no new errors or CSP violations.
- [ ] Both board docs and 1.5.0 changelogs are updated; Speech to Text declares `audio@1` and 5.0.18/1.51.0 minimums, while Agent Chat retains its existing declaration and minimums; manual checks cover local and external transcription, lifecycle and backpressure. No unit tests or test harnesses are added.
