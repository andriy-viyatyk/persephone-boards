## Goal

Extend live dictation so stable words appear during continuous speech in short groups, rather than waiting for a 1200 ms pause or the 25 s utterance cap. Keep the live v1 contract, pause/cap finalization, language latch, helper-failure fallback, and local-only audio handling intact.

## Background

- **Epic/task order:** Persephone EPIC-134 phase 2, task 3 of 6. This task supersedes EPIC-134's proposed audio left-context task: committed text remains in the prompt, while the audio window starts at the latest safe committed Whisper segment boundary.
- **User report:** continuous speech currently produces one large block after roughly 15 s because commits wait for a 1200 ms pause or the 25 s cap. Desired behavior is Windows Win+H-like insertion in groups of 2–4 words, about 1.5–2.5 s after they are spoken.
- **Accepted design:** while speech continues, re-run inference about every second over the current uncommitted audio window. Compare consecutive hypotheses with LocalAgreement-N (default N=2; measure N=3): emit the longest common word prefix after the committed-window alignment as a `segment`, and keep the remaining latest hypothesis as the `draft`. Normalize comparison words by Unicode-aware case folding and punctuation stripping, including Ukrainian/Cyrillic; emit original spelling from the latest hypothesis. Before language latch, a partial commit requires N agreeing hypotheses to report the same language; it may set the latch when the window contains at least 2 seconds of speech.
- **Current live segmentation:** `scripts/live.mjs` detects speech with 0.5/0.35 hysteresis, keeps up to 1 s pre-roll, emits one draft after a 500 ms pause, commits after a 1200 ms pause, pads commits by 300 ms, and cuts at 25 s. `Segmenter` currently emits a single `draft` or `commit` range per utterance; `LiveStream` retains PCM slices.
- **Current service:** `scripts/service.mjs` serializes whisper jobs in one FIFO queue. Drafts can be discarded as stale, but commits are retained. `allowedLanguages()` prefers caller-supplied hints, otherwise the board's `language-hints` setting; `infer()` forces the only allowed language when the resulting list has one code. Thus a single-code board language setting (or caller hint) is used from the first pass. BT-061 currently prompts with the base prompt plus up to 200 characters of committed text, regardless of whether that text's audio remains in the live audio range; it sets `response_format=verbose_json` and `no_timestamps=true`. Partial mode changes the prompt rule: append only the tail (at most 200 characters) of committed text whose audio has already been trimmed before the current window start. Final commits in partial mode use this same prompt rule. BT-061 currently latches on a final commit with at least 2 seconds of speech; BT-062 allows a qualifying same-language partial commit to latch as well. Helper failure invalidates drafts and commits the uncommitted tail at end.
- **Whisper response evidence:** the installed `whisper-runtime-1.9.5-r2/README.txt` identifies upstream whisper.cpp v1.9.5, commit `d1be6fde11ac6e0407606b4e42fe72d34add8037`. An existing saved `verbose_json` response from the same upstream v1.9.5 runtime (r1) has root keys `task`, `language`, `duration`, `text`, `segments`, `detected_language`, `detected_language_probability`, and `language_probabilities`. Each segment includes `id`, `text`, `start`, `end`, `tokens`, `words`, `temperature`, `avg_logprob`, and `no_speech_prob`; each `words` item includes `word`, `start`, `end`, `t_dtw`, and `probability`. Therefore segment and word timing fields exist when timestamp output is enabled. The present service explicitly disables timestamps, so this response cannot be assumed from current requests; verify the exact r2 response with timestamps enabled before relying on it for trimming. The saved sample's server log identifies r1, so it is evidence for the v1.9.5 response shape, not a direct r2 runtime probe.
- **Consumer contract:** `C:/projects/persephone/assets/guides/agents/speech-transcribe.md` currently allows ordered segments per utterance and says `result.text` joins the nonempty segment texts with one space; it does not yet explain several partial `segment` messages for one utterance, each carrying only new text.
- **Voice Typing consumer check:** `C:/projects/persephone/src/renderer/ui/voice-typing/VoiceTypingController.ts` already queues every `segment` message for insertion and tracks drafts by utterance ID in `draftUtterances`; each segment clears that utterance's draft. Its auto-stop check requires `draftUtterances.size === 0`, so verify that repeated partial drafts after partial segments keep auto-stop suppressed while a draft is active, and that no draft arrives after the utterance's final segment. It can accept several segments for one utterance; no code change is currently identified.
- **Agent Chat consumer check:** `boards/claude-agent/app.js` currently opens a non-live provider channel and handles only status, result, and error; it does not consume live draft/segment events. The separate EPIC-134 Agent Chat live insertion task remains responsible for that UI. Confirm it still tolerates the final result contract when it is implemented.
- **Board settings:** `board-manifest.json` currently has language hints, vocabulary prompt, GPU, idle-unload, and caller-approval settings. These tuning values affect recognition latency/stability and are proposed as internal constants first; recommend considering a board setting only if testing shows a user-facing tradeoff that needs runtime adjustment.
- **Verification precedent:** BT-061 verified live behavior through the Speech to Text board page and Persephone MCP, using the local `en-pauses.wav` fixture streamed in real time. Do not add unit tests or a committed test harness. Test recordings remain on the user's machine and are not uploaded.

## Decisions

- **Defaults:** N=2, `minNewWords=2` during speech, 12 s minimum window before considering trim, and partial fallback after three consecutive forced-language passes longer than 1500 ms. Auto-detect passes do not count toward this fallback. N=3 is a verification comparison, not the default.
- **Remainders:** pause/cap/end commits emit any remaining aligned text, including a single word.
- **Prompt and audio context:** prompt only with committed text whose audio has been trimmed out; do not trim until the window exceeds `trimAfterMs` and a fully committed segment end is available. If timestamps cannot be used, do not trim and let bounded-window pause/cap behavior finalize.
- **Language:** `allowedLanguages()` uses caller hints when present, otherwise board `language-hints`; when exactly one code is allowed, `infer()` forces it from the first pass. Otherwise partial passes auto-detect before latch and LocalAgreement-N commits require same-language hypotheses. A qualifying partial commit may latch when its window contains at least 2 s of speech; otherwise the first qualifying final commit retains the BT-061 latch behavior.
- **Slow-pass fallback:** only forced-language partial passes count toward the consecutive slow-pass threshold. BT-058 measured a 2.5 s clip at about 1.2 s with language forced versus about 2.2 s with auto-detection on GPU, so auto-detection time is not evidence that the forced-language partial loop cannot keep up.
- **Settings:** no new `board-manifest.json` settings are recommended initially; keep tuning in the single code object unless testing establishes a user-facing setting need.
- **Consumers:** Voice Typing is verified in code to queue each segment, track draft utterance IDs, and suppress auto-stop while `draftUtterances` is nonempty. Repeated partial drafts and the no-draft-after-final-segment guarantee remain explicit runtime verification criteria. Agent Chat still has its separate live insertion task.

## Acceptance Criteria

## Verification (Claude, 2026-10-27)

Driven from the Speech to Text board page through Persephone MCP, streaming at real-time pace in 100 ms chunks, warm engine, GPU, English forced. Fixtures stayed local: `en-pauses.wav` (38.2 s, pauses) and `en-fast.wav` (26.8 s, the same speech with silences collapsed to 120 ms).

- **r2 timestamp probe:** `no_timestamps=false` on `whisper-runtime-1.9.5-r2` returns `segments[]` with `start`/`end` in seconds. Segment timing is unreliable at the end of a pass: the last segment is often squashed to near-zero length (e.g. 8.61–8.62 s) and the one before it is stretched over its audio. Zero-length punctuation-only segments (`","`) also occur.
- **N=2, `en-fast`, 5 runs:** every final text complete (no lost or repeated words); a segment every ~1.2–1.4 s with occasional 2.5–4.8 s gaps; 2–6 words per segment; words appear roughly 1.5–2.5 s after being spoken. Pass time 1.1–1.6 s.
- **N=3, `en-fast`, 4 runs:** same completeness, one extra pass (~1.3 s) of delay per word, longer worst gaps (up to 6.5 s). N=2 kept as the default.
- **`en-pauses`:** pauses still commit utterances; long utterances arrive in small pieces. One recognition difference ("in the main window" for "and the main window"), not a live-mode loss.

### Fixes made during verification

- Two undefined references (`event` in the `pumpQueue` finally block, `job` in the rejected-partial path) would have crashed the service on the first pass.
- Emitted text was rebuilt from punctuation-stripped tokens; it now keeps the whitespace tokens of the latest hypothesis (punctuation and case kept, comparison still normalized).
- `maxPassMs` 1500 disabled partials after ~12 s (passes take 1.1–1.6 s); now 3000. `trimAfterMs` 12000 → 8000 to keep windows short.
- Trimming at a stretched segment end cut audio of uncommitted words and left committed words whose audio was gone, which stalled agreement for the rest of the utterance. A segment end is now trusted only when a following segment has a plausible duration (≥ 0.3 s and ≥ 0.2 s per word) and lies at least 1 s before the window end.
- Alignment with no anchor in the hypothesis now treats the hypothesis as new text (committed audio was trimmed) instead of discarding it; the anchor search is limited to the start of the window; trimmed words are no longer aligned against.
- Hypotheses are rebased after a trim instead of cleared, removing a two-pass gap.

### Fixes after the user's Ukrainian test (2026-10-27)

The user reported a first print after 10–12 s, repeated phrases, words split across pieces ("т екст") and long stalls followed by a whole sentence.

- **Language:** voice typing sends no languages, so the board default `uk,en` applies and every pre-latch pass auto-detects. Whisper often detects Ukrainian as Russian, and such passes were discarded. A pass whose detected language is not allowed now reruns with the likeliest allowed language (falling back to the first). Auto-detecting passes measured 3–5 s on the GPU against ~1.2 s forced, so the first pass with at least `languageLatchSpeechMs` (1000) of speech now fixes the stream's language. English with `uk,en`: first piece at 4.3–6.3 s, down from 8–9 s.
- **Split words:** two passes ending on the same half-word agreed on the fragment. The last word of the latest pass is now never committed while speaking.
- **Repeated phrases:** Whisper rewrites committed words between passes ("14" → "14-й", "фраз" → "фраза"), so exact alignment failed and the no-anchor fallback re-emitted them. Alignment now treats a word and a variant differing only by up to two trailing characters (prefix ≥ 2 characters) as the same, and a hypothesis with no anchor skips the committed word count again; with plausibility-checked trims the committed words remain in the window.

- **Words split by a space (second Ukrainian test, "т екст", "деся ть"):** with timestamps on, whisper-server splits segments at `max_len` 60 characters on token boundaries and joins segment texts with a newline, so a split inside a multi-token word became two words. Requests now send `split_on_word=true`.
- **Tried and reverted:** a per-request `audio_ctx` sized to the window (to skip encoding the 30 s padding) made passes loop and stall into the slow-pass fallback; removed.

- **Long gaps between passes with real speech (third test):** passes ran only while the VAD reported speech, and every resumed run of speech reset the next pass to one second later. Natural speech has many short gaps, so passes were skipped for 3–5 s at a time (the collapsed-pause fixture hid this). The pass schedule now carries across short gaps inside an utterance, and up to `agreementCount` passes run during a pause. `en-pauses`: a piece every ~1.2 s, 2–5 words, from 5.4 s.
- **User acceptance (2026-10-27):** in the user's Ukrainian and English dictation through voice typing the first piece arrives at ~8 s and then 2–6 words at a time; the user accepted this and asked to stop tuning.
