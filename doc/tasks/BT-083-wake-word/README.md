## Goal

Build a local, enrollment-based `speech.wake@1` provider for wake and stop phrases and a board page for hands-on enrollment and measurements. The voice assistant and the rule comparing microphone and loopback detections belong to Persephone's US-1786, not this board.

## Background

- Normative contract: `C:/projects/persephone/assets/guides/agents/speech-wake.md`; service and security rules: `C:/projects/persephone/assets/guides/agents/boards.md`. EPIC-139 decisions 2, 2a, 3a and 10 assign engines and voice data to providers, enrollment to each person, the two-stream comparison to the app, and microphone ownership to the app's visible normal window. BT-083 follows US-1783 and US-1784; BT-082, BT-083 and US-1785 can run in parallel before US-1786.
- `C:/projects/persephone/doc/tasks/US-1783-wake-word-research/README.md` records the accepted query-by-example method: 96-dimensional embeddings every 80 ms from a 0.8 s window, subsequence DTW over cosine distances, approximately five utterances per phrase/person, and a provisional distance threshold of 0.15. The board simulation cost about 5% of one core; film, simultaneous voice and film, and TV loopback-to-mic delay remain unmeasured; BT-083 measures microphone-only film triggers, and US-1786 owns the two-stream measurements. Earlier sherpa-onnx keyword-spotter figures and its threshold are not measurements of the chosen engine. `C:/projects/test-boards/wake-word-test/` is the rejected keyword-spotter prototype, for reference only.
- `C:/projects/test-boards/wake-enroll-test/scripts/service.mjs` loads `model/melspectrogram.onnx` (1,087,958 bytes) and `model/embedding_model.onnx` (1,326,578 bytes) through `onnxruntime-node` 1.31.1. Research identifies both as openWakeWord's packaged feature models: the mel frontend implements a spectrogram and the embedding derives from Google `speech_embedding`. Research treats openWakeWord's included model files as CC-BY-NC-SA; do not redistribute either prototype file. Kaggle API metadata and the downloaded source digest are recorded in Gate results; preserve the Apache-2.0 attribution and dependency notices before distribution.
- The prototype trims by a 20th-percentile noise floor, computes normalized vectors, and stores templates plus WAVs in `enroll/`; it also records `last-session.wav`. Its page and worklet capture and resample microphone audio, but its float messages, responses, storage and single-person-only identity are not the v1 contract. Do not carry over its audio recordings. `boards/speech-to-text/scripts/service.mjs`, `downloads.mjs`, `audio-capture-worklet.js`, UI and language packs show channels, explicit verified downloads, streaming capture, settings and provider declaration. `boards/translate/scripts/bergamot-worker.mjs` loads a vendored WASM runtime in a service worker; `boards/translate/vendor/` totals 6,347,920 bytes (~6.1 MiB). Neither precedent uses ONNX in its board source; Speech to Text downloads a separately versioned Windows runtime. `scripts/publish-board.mjs` excludes every `node_modules` directory, so the prototype's local npm installation will not ship.
- `how-to/README.md` lists no recipe about board services, models or interfaces. The running app's boards guide confirms channel backpressure and service interface declarations.

## Gate results

**2026-11-07 — Gate 1 PASSED as equivalent by reviewer; Gate 2 passed.** The reviewer overrides the failed verdict recorded at the end of the original comparison below. The source provenance is `_test/wake-export/google-release/kaggle-model.json`, returned by Kaggle's model API (`https://www.kaggle.com/api/v1/models/google/speech-embedding/get`). It identifies the `tensorFlow1` instance, version 1 (`versionId: 1535`), with `licenseName: Apache 2.0`; the description documents 16 kHz float32 `[-1,1]` input and internal 32-bin log-mel (25 ms window, 10 ms step, 60–3800 Hz). Attribute as “speech_embedding” by Google, Kaggle/TF Hub, Apache-2.0, and cite Lin et al. 2020, [Training Keyword Spotters with Limited and Synthesized Speech Data](https://arxiv.org/abs/2002.01322). The downloaded compressed source is 1,336,273 bytes, SHA-256 `0f626c42009c1eb916401b7b2800229a211e43100115bc591b9afbf1b60da27f`. Export used Python 3.12, TensorFlow 2.16.2, tf2onnx 1.16.1, ONNX Runtime 1.20.1 and NumPy 1.26.4. ONNX opset 13 output is 1,332,551 bytes, SHA-256 `afba79cbf9a64b9281573bb1f8cba1925f8942b40da206a26cb6e81dd6d32234`; input `Squeeze:0` float32 `[1,76,32]`, output `embeddings_apply_default/MudpuppyLite/Conv_18/Conv2D:0` float32 `[1,1,1,96]`. The JS frontend is 16 kHz, 400-sample periodic Hann, 160-sample hop, 512-point FFT magnitude, 32 mel bins from 60–3800 Hz and `ln(mel + 0.001)`. A 12,800-sample window yields 78 frames; JS frontend vs. TensorFlow had max absolute error 0.00000692 and RMSE 0.000000887. Full release vs. clean ONNX embedding cosine was 1.000000 (max absolute vector error 0.000000231); random-feature TensorFlow vs. ONNX cosine was 0.99999994 (max absolute error 0.0000205).

The decisive test replayed the 42.28 s existing `last-session.wav` in 528 80 ms chunks. Prototype openWakeWord files were used only as reference and were not copied. The best-distance trace min / 5th percentile / median was prototype 0.0597 / 0.0844 / 0.2379 and clean 0.0463 / 0.0655 / 0.2508. No clean threshold gives the prototype's exact event set. At clean distance 0.16303 (score threshold `1 - d = 0.83697`), all six prototype events can be paired within one 80 ms hop, but two extra events appear at 5.44 and 32.00 s. That threshold's additional-region margins are -0.1124 and -0.0992; its 23.92 s region margin is -0.1167. The reviewer decision is that exact event-set equality is not a valid equivalence bar: the clean export reproduces Google's Apache-2.0 release exactly (cosine 1.000000); on `last-session.wav`, both pipelines fire six events at distance 0.15, with four events at identical times; and neither pipeline's weak region margins make the prototype ground truth (prototype margins -0.081…+0.013; clean -0.099…+0.0004). The prototype openWakeWord models cannot ship under CC-BY-NC-SA. Gate 1 therefore PASSES as equivalent for this implementation. Keep provisional `defaultThreshold` at 0.85 (distance 0.15); calibrate the final value in the user-assisted live enrollment test.

## Concerns / Open Questions

- **Export is the first and binding gate.** Google's release may expose a waveform-to-embedding graph rather than the prototype's intermediate `[1,76,32,1]` input and `conv2d_19` output, and conversion may fail or produce materially different results. Inspect the actual release and prove the JS frontend and ONNX backbone reproduce behavior before proceeding. If the necessary frontend is non-trivial or cannot be reproduced in JS, report it and stop; never substitute openWakeWord's restricted packaged models.
- The 0.85 default is a direct conversion of a small research sample, not a validated false-trigger rate. Speech/noise gating and frontend differences can change recall and event timing. User-assisted microphone film playback and real voices must inform calibration.
- A board cannot capture loopback: `C:/projects/persephone/src/main/permission-policy-service.ts` limits the Windows display-media grant to the armed Transcript app main frame. BT-083 measures film triggers on the microphone only. US-1786, using app capture, owns the deferred film comparison on both streams, simultaneous film and voice, and loopback-to-microphone delay, as well as the time-matching rule. No virtual device or external WASAPI harness is part of this task.
- WASM service compatibility and CPU cost are unverified; the native fallback is conditional on an actual failed performance budget and must be verified with the host. Enrollment embeddings retain voice information; explain retention and deletion without claiming anonymity.

## Live verification (2026-11-07, Persephone dev build)

Checked from the app side through `api.connectHostServiceChannel("speech.wake")`, with enrollment and test audio synthesized by the Text to Speech board (no microphone, no real voices):

- `describe`: `local: true`, `features: []`, `defaultThreshold: 0.85`, `maxEnrollMs: 3000`. `listen` with nothing enrolled: `no-enrollments`. Invalid delete target: `invalid-argument`.
- **Bug found and fixed (reviewer):** short names were rejected as `short` — the clip trimmed to speech ±100 ms is shorter than the 775 ms the model needs for its first embedding, so `encodeSamples` produced nothing. `scripts/engine.mjs` now pads one model window of silence before an enrollment clip, as the research prototype did, and skips windows lying entirely in the padding.
- After the fix: 5 of 5 "Persy!" samples (speeds 0.9–1.1) accepted; `match` against earlier samples 0.727–0.746.
- Listen over a 15 s stream (WASM in the board service, 8.5 s of audio processed in ~0.3 s): `wake Persy` at 6.90 s (name 6.21–7.54 s, score 0.883) and at 14.20 s for a different synthetic voice (13.53–14.75 s, score 0.879). No event for an unrelated sentence, nor for a sentence mentioning "Percy".
- `delete { person }` removed 5 samples; `list` then empty. `ui.log` clean.
- Observation for the user test: enrollment `match` values (~0.73) run lower than detection scores for the same audio (~0.88), because enrollment compares whole clips; the page should not read them against the detection threshold.
- **Bug found and fixed (reviewer):** the board page's own channels were all refused — `allowed()` and the diagnostics check required `info.page.boardId === "wake-word"`, but `boardId` is the page instance id. Own page is now "no `info.interface`" (`isOwnPage()` in `scripts/service.mjs`), as in Speech to Text. Before the fix the page could not list, enroll or listen.
- **Layout fix (reviewer):** the Microphone select overflowed its card; `label > input, label > select` now fill their grid cell.
- `screenshot.png` captured (1120×700) with synthetic "Demo" enrollments and a generic microphone label; the demo enrollments were deleted afterwards.
