# BT-072: Agent Chat profile management through AI Vision

## Status

**Status:** In Progress  
**Priority:** Medium  
**Board id:** `claude-agent`  
**Started:** 2026-10-29  
**Completed:** —

## Goal

Publish a curated `window.persephone.aiVision` object model for Agent Chat profiles so an agent using `pages[id].editor.app` can list, read, create, update, duplicate, and delete profiles, and inspect valid provider/model/effort choices. Keep profile persistence and validation on the existing `manage-profiles` service path.

## Background

- Agent Chat currently edits profiles through the Configure dialog. `profileRequest()` opens a `manage-profiles` service channel, and `refreshProfileCatalog()` loads the profile list and provider descriptions (`boards/claude-agent/app.js:922-937`). The form contains `name`, `roleTitle`, `instructions`, `summary`, `provider`, `model`, `effort`, and `permissionMode`; `profileDraft()` serializes those fields plus the stable `id` (`boards/claude-agent/app.js:939-943`).
- The Configure save handler requires non-empty name, role title, instructions, and summary (`boards/claude-agent/app.js:987-990`), while the service validator currently checks header safety and text types/size but does not reject empty instructions or summary (`boards/claude-agent/scripts/service.mjs:92-109`). Make those required-field rules authoritative in the service validator so AI Vision writes and Configure saves share the same validation. `profileRequest()` currently discards the service's detailed `profile-error.message` and rejects with a generic localized error (`boards/claude-agent/app.js:923-929`); preserve that UI behavior while allowing model methods to return readable validation details to the agent.
- `profileRequest()` also has a no-op `onClose` handler, so a channel that closes before either expected response can leave the promise pending (`boards/claude-agent/app.js:923-931`). Reject on close-before-reply and carry the service message on the Error (for example `error.detail`); keep the Configure UI showing `t("profiles.error")`, while AI Vision methods throw the detailed message.
- The service is the existing source of truth: it reads/writes `%LOCALAPPDATA%/Persephone/board-data/claude-agent/group-chat/profiles.json` (`boards/claude-agent/scripts/service.mjs:30-34,71-81`). It validates the exact profile fields, provider, model, effort and permission preset (`boards/claude-agent/scripts/service.mjs:83-109`).
- The local board-page discovery handler already supports `get`, `save`, `delete`, `duplicate`, and `reset`. `save` creates or replaces by id and persists; duplicate persists; every response includes provider descriptions with their model catalogs (`boards/claude-agent/scripts/service.mjs:672-694`). The current `delete` branch filters the returned list but does not write it to `profiles.json` (`boards/claude-agent/scripts/service.mjs:680-682`); fix that existing branch to persist via `atomicJson()` as part of this task. The service has a separate `agent.session` group operation path too, but direct `manage-profiles` channels from interface/caller origins are refused as local-page-only (`boards/claude-agent/scripts/service.mjs:752-755`). The AI Vision methods should run in the Agent Chat board frame and call its existing `profileRequest()` helper; they must not open a new cross-board service/API path.
- Provider descriptions include dynamic model rows and per-model effort choices. The Codex adapter returns model ids, supported reasoning efforts, and availability (`boards/claude-agent/scripts/providers/codex.mjs:390-403`); the Claude adapter returns aliases and discovered model rows (`boards/claude-agent/scripts/providers/claude.mjs:969-980`). The Configure UI already derives those options from the descriptions and handles Claude aliases (`boards/claude-agent/app.js:948-966`).
- An Agent Chat page session can reach Persephone through MCP when its private endpoint is attached. The service attaches that endpoint unless `mcp.persephone` is false or the effective mode is `read-only` (`boards/claude-agent/scripts/service.mjs:297-318`); Claude and Codex adapters pass the endpoint to their provider process (`boards/claude-agent/scripts/providers/claude.mjs:535-538,764-772`; `boards/claude-agent/scripts/providers/codex.mjs:81-86,302-318`). Thus the main Agent Chat session has access by default; joined read-only profiles do not, while other joined profiles do unless MCP is disabled. The feature serves external MCP agents too.
- Configure saves replace the current profile array and rerender the editor (`boards/claude-agent/app.js:987-996`); openConfig fetches fresh profiles when opening the dialog (`boards/claude-agent/app.js:1193-1204`). External AI Vision writes therefore need a deliberate refresh policy: update shared app/group profile state and future invite choices, but never rerender or replace a dirty `profileEditor` draft. If Configure is open and dirty, defer reconciling its list/form until the draft is resolved; reopening Configure must fetch the latest service data. Existing local saves continue to use their current unsaved-change flow (`boards/claude-agent/app.js:998-1027`).
- Expose profiles as a read-only indexed collection with an item descriptor for `id` and the eight profile fields. Create/update/delete/duplicate use `profileRequest()` and the service; deletion is immediate and carries a destructive `caution`, without waiting on a Configure confirmation dialog. Duplicate reuses the service's generated unique name and id (`boards/claude-agent/scripts/service.mjs:85-90,680-688`).
- Exact root member names: `profiles`, `providers`, `permissionModes`, `create(fields)`, `update(id, patch)`, `duplicate(id)`, and `delete(id)`. `profiles` is read-only and indexed; each profile item has read-only `id`, `name`, `roleTitle`, `instructions`, `summary`, `provider`, `model`, `effort`, and `permissionMode` properties. Do not expose the service's `reset` action.
- Define method arguments and results: `create(fields)` accepts a partial object, applies the Configure new-profile defaults for omitted `provider`, `model`, `effort`, and `permissionMode` (`claude`, `opus`, `medium`, `read-only`; `boards/claude-agent/app.js:1019-1022`), generates `id` with `crypto.randomUUID()`, and returns the saved profile record. `name`, `roleTitle`, `instructions`, and `summary` have no defaults and remain required. `update(id, patch)` fetches the latest record with `profileRequest("get")`, merges the partial patch, rejects unknown keys and any `id` key, saves and returns the saved record. `duplicate(id)` returns the copied profile record. `delete(id)` rejects if absent and returns the deleted id.
- Recommend rejecting profile names that match another profile case-insensitively. Enforce this in the shared service save-validation path, excluding the profile currently being updated, so Configure and AI Vision writes use the same rule; current save validation does not check for duplicate names (`boards/claude-agent/scripts/service.mjs:92-109,672-680`).
- Describe the four `permissionModes` and `permissionMode` values explicitly: `read-only` permits read-classified tools and denies other actions; `ask` requests approval for non-read actions; `auto-edit` allows file writes inside the working directory and requests approval for other non-read actions; `full-auto` allows all classified actions (`boards/claude-agent/scripts/agent-session-protocol.mjs:70-92`; `boards/claude-agent/scripts/service.mjs:286-295`). A caller can create or raise a profile to `full-auto`; this is accepted because MCP callers already have app-scripting power and Configure exposes the same choices (`boards/claude-agent/board-manifest.json:15-23`; `boards/claude-agent/app.js:975-978`).
- The AI Vision authoring guide says the shim is supplied to every board frame, should be guarded for standalone/older hosts, and publishes the model with `aiVision.expose()` (`C:/projects/persephone/assets/guides/agents/ai-vision.md:74-92,154-164`). Collections should be indexed, and agent-facing methods must not block on in-board dialogs (`C:/projects/persephone/assets/guides/agents/ai-vision.md:142-152,247-259`). The Boards `.app` reference places the model at `pages[pageId].editor.app` and documents `refresh()` for indexed shapes (`C:/projects/persephone/assets/guides/agents/boards.md:1235-1264`).
- Keep scope on profiles. Do not add a session summary or expose unrelated session controls. Duplicate and delete are useful alongside the requested profile CRUD, with deletion marked destructive.
- No additional manifest declaration is needed for `aiVision`: Persephone injects the shim into board frames (`C:/projects/persephone/assets/guides/agents/ai-vision.md:74-92`). Profile operations use the existing service channel rather than `persephone.call()`. The manifest already grants `service` and `appScripting` (`boards/claude-agent/board-manifest.json:15-23`); do not add a permission for this model.
- Version `1.3.2` was already published by commit `d014b0a`. Commits `6b91557` (session ring/working light, reporting working state to Persephone) and `cb40866` (voice recording continues while the board is hidden) changed the board afterward without a version bump or changelog entries. The next release should be `1.3.3`, and its `WHATS-NEW.md` section must include lines for both carried-forward changes and BT-072. README already documents profile editing and stored fields (`boards/claude-agent/README.md:17-23`); add a short note describing MCP/AI Vision profile management. No page UI text is required for the model API, so no new translation keys or `lang/*.json` edits are expected.

## Implementation Plan

1. In `boards/claude-agent/app.js`, add an AI Vision descriptor and guarded `expose()` call after the main page state and DOM are initialized. Keep the descriptor's member names and profile field names in English. Publish the current profile collection and current provider descriptions; refresh indexed shape when the profile collection transitions between empty and non-empty.
2. Implement the exact read/catalog members `profiles`, `providers`, and `permissionModes`: `profiles` is a read-only indexed collection; `providers` lists provider ids, availability, model ids, and each model's supported efforts; `permissionModes` lists `read-only`, `ask`, `auto-edit`, and `full-auto` with the permission effects described above. Document those effects on the `permissionModes` member and `permissionMode` profile property. Refresh through `profileRequest("get")` when needed and return concise JSON rather than UI labels alone. The complete root member list is `profiles`, `providers`, `permissionModes`, `create(fields)`, `update(id, patch)`, `duplicate(id)`, and `delete(id)`.
3. Implement exactly `create(fields)`, `update(id, patch)`, `duplicate(id)`, and `delete(id)` using only `profileRequest()` and existing actions. Create fills Configure defaults, generates an id, rejects unknown fields, validates required fields, and returns the saved record. Update fetches fresh data, requires a partial object, merges the patch, rejects unknown keys and attempts to change `id`, then returns the saved record. Duplicate returns the copied record; delete rejects absent ids and returns the deleted id. Repair the existing `manageProfiles` delete action to persist through `atomicJson()`, align `validateProfile()` with Configure's required fields, and reject case-insensitive duplicate names in the shared save path. Apply name uniqueness only on writes (not `readProfiles()` validation of existing data), excluding the record being updated. Do not add a store, `reset` method, or new service API. Make `profileRequest()` reject on close-before-reply and retain detailed service errors for model methods while Configure continues to show its localized generic message. Mark delete as immediately destructive in its member `caution`.
4. Reconcile successful method results with shared `state.profiles` and active group invite choices. If Configure is closed or clean, synchronize its list while preserving selection; if its draft is dirty, preserve the form and defer editor reconciliation until the draft is resolved. Ensure a later dialog opening always refreshes from the service.
5. Update `boards/claude-agent/README.md` with the agent-facing profile API and permission descriptions, bump `boards/claude-agent/board-manifest.json` to `1.3.3`, and add a `1.3.3` section to `boards/claude-agent/WHATS-NEW.md` with lines for BT-072 and the unbumped changes from `6b91557` and `cb40866`; `1.3.2` is already published in `d014b0a`. Limit `scripts/service.mjs` changes to existing profile CRUD/validation and delete persistence; do not add a store or new service API. Do not change manifest permissions or add translations unless implementation introduces localized UI text.

## Concerns / Open Questions

- Resolve profile-list refreshes without discarding a dirty Configure draft. If the same profile changes externally while its local draft is dirty, the implementation should surface a conflict or defer the refresh rather than silently replacing either copy.
- `permissionMode` values must remain the service's existing four values: `read-only`, `ask`, `auto-edit`, and `full-auto` (`boards/claude-agent/scripts/service.mjs:83-100`). A model caller can set or raise a profile to `full-auto`; this is accepted because MCP callers already hold app-scripting power and Configure allows the same choice (`boards/claude-agent/board-manifest.json:15-23`; `boards/claude-agent/app.js:975-978`). Describe each preset's effects in the model so the caller can choose deliberately (`boards/claude-agent/scripts/agent-session-protocol.mjs:70-92`).
- In-board main Agent Chat sessions have Persephone MCP attached by default, and joined sessions with a non-`read-only` profile can also receive it; read-only joined sessions do not (`boards/claude-agent/scripts/service.mjs:297-318`; `boards/claude-agent/scripts/providers/claude.mjs:535-538,764-772`; `boards/claude-agent/scripts/providers/codex.mjs:81-86,302-318`). External MCP agents can use the same model.
- Case-insensitive profile-name uniqueness is a recommended rule. Add it in shared save validation, excluding the current record on update, so Configure follows it too (`boards/claude-agent/scripts/service.mjs:92-109,672-680`).
- The service validates model/effort against the provider's current catalog (`boards/claude-agent/scripts/service.mjs:102-109`), so the catalog method should return current descriptions and method errors should explain when a provider is unavailable.
