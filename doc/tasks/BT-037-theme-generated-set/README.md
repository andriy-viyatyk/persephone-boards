## Goal

Add a Generated Set view before Generator and Details. It creates 100 contrast-ranked theme variants, sorts them by background hue, and lets a click apply a tile to the shared draft and live preview.

## Background

- **Verified current view structure:** `index.html:36-55` has Generator then Details tabs and panels; `app.js:370-377` permits only those two views and hides the Starting palette sidebar section on Generator, leaving it visible on Details. `state.view` defaults to `"generator"` (`app.js:66-78`). The new view should hide Starting palette, matching Generator, because the tile set replaces both the base-color controls and the detailed palette as the main content; keep Contrast visible.
- **Verified candidate and application behavior:** `makeRandomCandidate()` is already the random-color source (`app.js:393-422`): backgrounds use a 20% vivid chance (`app.js:387-392`), background polarity follows explicit mode or chooses dark/light when the draft is Auto, and Text/Accent colors follow the background hue and polarity. Locks are checked by candidate generation (`app.js:395-419`) and `randomizeCore()` removes locked blocks from its selected set (`app.js:445-459`). It tries up to 20 candidates, ranks by passing required pairs then lowest ratio (`app.js:424-430, 467-485`), and currently applies the winner through `releaseSourceExact()`, draft base assignment, optional mode/polarity sync, control sync, `onDraftChanged()`, and `queueDraftRefresh()` (`app.js:489-496`). `makeRandomCandidate()` currently clones the complete draft, including source-exact overrides; Generate then drops those overrides when applying (`app.js:393-395, 489-496, 718-723`). Fix this once with a `generatorSource()` helper used by both `randomizeCore()` and set generation: clone the draft, remove keys in `state.sourceExact`, and retain only hand-set Details overrides for scoring. Factor the apply sequence into one helper used by Generate and tile clicks.
- **Verified derivation and performance boundary:** the board bridge exposes `derive(base, isDark?)` and `contrast(input)` as async JSON calls (`C:/projects/persephone/assets/guides/boards.md:927-954`); renderer implementation delegates directly to `deriveTheme()` and `contrastReport()` (`C:/projects/persephone/src/renderer/api/themes.ts:76-82`). Existing refresh computes derive and contrast in parallel, then previews, guarded by a generation check (`boards/theme-editor/app.js:1105-1129`). The current code comment estimates ~10 ms for derive + contrast + preview (`app.js:1085-1088`); BT-036 records a live measurement of about 1 ms per derive/contrast and 2–7 ms per preview (`doc/tasks/BT-036-theme-generator/README.md:104`). Those are compute observations, not serial postMessage round-trip latency for 100 variants. Keep **at most 2 contrast attempts per tile**, retain the better `rankContrast()` result, stop early if all four required pairs pass, and call `derive()` once for each retained candidate. Run variants concurrently in bounded batches of 10–20 with `Promise.all`; measure elapsed time in the live check and tune batch size while keeping the two-attempt cap. Tiles need no preview during candidate search.
- **Verified random-check and rendered palette semantics:** the four existing required checks are `text-default/bg-default`, `text-selection/bg-selection`, `primary-text/primary-bg`, and `misc-link/bg-default` (`app.js:52-53`); candidate reports are already ranked with `rankContrast()` (`app.js:424-430`). Render each tile as its derive result with remaining hand-set overrides layered over `derived.colors` by their `--color-*` keys, matching what apply will show. Source-exact overrides are removed from candidate scoring and the shared apply path releases them; hand-set Details overrides remain (`app.js:718-723, 489-496`).
- **Verified derive keys for the mock window:** render the content surface with `--color-bg-default`; title bar with `--color-bg-dark` and `--color-text-strong`; toolbar with `--color-bg-light`; content text with `--color-text-default` and muted/disabled sample text with `--color-text-light`; outlines with `--color-border-default` and `--color-border-light`; accent button with `--color-primary-bg` and `--color-primary-text`; optional selection/hover tint with `--color-bg-selection` and `--color-text-selection`. These keys exist in the declared theme variable list (`C:/projects/persephone/src/renderer/theme/theme-color-vars.ts:2-79`); the derivation assigns the background, text, border, selection and primary values (`C:/projects/persephone/src/renderer/theme/custom-theme.ts:194-254`). The mock-up is decorative (`aria-hidden="true"` and/or `inert`, no buttons/inputs, no per-tile listeners); all surrounding board chrome stays on `--p-*` variables (`C:/projects/persephone/assets/guides/boards.md:1000-1039`).
- **Verified intent and initialization flows:** Settings `new` intent currently copies the active source draft, removes its id and overrides, and retains the fork's `isDark` value (`app.js:1000-1007`); edit loads its requested theme (`app.js:1015-1018`). Set `draft.isDark = null` in the `new` branch: Auto infers the same polarity from the copied background, preserving initial appearance while allowing Generated Set to mix modes. An explicit Dark/Light choice produces only that polarity. Intent processing is queued after acceptance (`app.js:1063-1083`). Make `new` select Generated Set immediately and generate it; make `edit` select Generator; leave ordinary startup/restored drafts on Generator. Generate the first set lazily on first manual selection. Keep the set in memory only; current `pageState` persistence is specifically the unsaved draft (`app.js:1539-1559`), and no persisted generated-set state is needed.
- **Verified AiVision model surface:** `exposeAiVisionModel()` declares `data-name` elements and currently names only Generator/Details view controls (`app.js:1378-1404`); its help describes those tabs and its `setView` signature allows only those values (`app.js:1405-1423, 1446-1448`). Its methods use `assertModelEditable()` for draft mutations (`app.js:1482-1498`). Add the Generated Set tab and Regenerate elements, extend `setView("set")`, and expose regenerate and apply-by-index methods that call the same guard. Event delegation on the tile container prevents listener growth across replacement renders.
- **Verified release metadata:** the board is currently version `1.0.3` (`boards/theme-editor/board-manifest.json:1-12`) and its changelog is headed `1.0.3` (`boards/theme-editor/WHATS-NEW.md:1-5`). Plan a `1.1.0` manifest bump with a matching changelog heading, and update `boards/theme-editor/CLAUDE.md` to document the additional tab, generation, and intent behavior. Publishing is outside this task.

## Concerns / Open Questions

- A locked Background means Auto polarity is inferred from that fixed background, so the set cannot include both dark and light variants while also honoring the Background lock. Preserve the lock and document that Auto produces a mix only when Background is unlocked; with Background locked, all variants follow its inferred polarity. If implementation uncovers a different interpretation for locks, keep it visible in the UI/help.
- Contrast ranking considers the four existing required pairs. Hand-set Details overrides remain in scoring and are layered over each tile's derive result, so each tile shows the same effective colors applying it will produce. Source-exact overrides are stripped from candidate scoring because the shared apply path releases them.
- The derive/contrast timings are compute observations from BT-036, not a measurement of serial postMessage latency. Two attempts cap the set at 300 bridge calls; bounded parallel batches and a live elapsed-time measurement will establish whether generation meets the 2 s target.
