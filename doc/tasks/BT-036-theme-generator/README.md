## Goal

Add a fast, guided way to create a theme by adjusting the three foundation colors and optional semantic colors, seeing Persephone's resulting palette, and randomizing safe starting points. Keep the existing exact per-variable editor as a Details tab on the same draft so users can switch to it for precise overrides without losing work.

## Background

- BT-034 established `boards/theme-editor/` as an offline plain HTML/CSS/JS board using `persephone.themes.*`. The draft shape is `{ schemaVersion, name, base, isDark, overrides }`; `derive(base, isDark)`, `contrast(draft)`, and `preview(draft)` remain the authority for palette derivation, contrast, and the app preview. The board may convert a chosen UI color between HSL and hex, but must not reproduce Persephone's derivation or contrast math.
- Current UI and state live in `boards/theme-editor/index.html`, `styles.css`, and `app.js`. `index.html` has a two-column `.workspace`: a left `.sidebar` with starting palette and contrast panels, and a main `.palette-area` for the current per-variable palette. The sidebar can remain in place while tabs switch only the main area's content. The current base/mode/override handlers mutate `state.draft` and call `onDraftChanged()` → `queueDraftRefresh()`.
- `queueDraftRefresh()` clears and resets a 120 ms timer, snapshots the draft, serializes work through `state.previewChain`, and uses `previewGeneration` checks around `derive()`, `contrast()`, and `preview()`. Repeated slider `input` events inside the debounce window coalesce; any already-started bridge call cannot be cancelled, but its generation check prevents stale results from rendering and the chain serializes the latest refresh. Preserve this path for generator controls; do not create a second preview pipeline.
- The reference `C:/data/js-notepad-notes/temp/format-test/color-palette-board/{index.html,app.js,style.css}` shows the intended control affordances: color well and hex field alongside H/S/L range sliders with live numeric outputs, a Random action, and visible color swatches/shade ramps. Reuse that interaction pattern only. Its hue harmonies, ramp generation, luminance, and contrast code are not Persephone's theme rules and must not be copied.
- Source verification: `C:/projects/persephone/src/renderer/theme/theme-color-vars.ts` declares the CSS variable names; `src/renderer/theme/custom-theme.ts` implements `deriveTheme()`, applies overrides in `buildCustomTheme()`, and computes the contrast report. `derive()` returns base-derived colors before overrides; the Generator's strips must be rendered from that latest result, with an explicit pinned marker when a draft override masks a strip variable. `Details` continues to show the effective editable rows and Reset controls.
- Verified base-input relationships from `custom-theme.ts` (relationships may also depend on inferred/explicit mode and other base inputs):
  - **Background (`base.background`)** directly supplies `--color-bg-default`; drives `--color-bg-dark`, `--color-bg-light`, `--color-bg-scrollbar`, `--color-bg-message`, `--color-border-default`, `--color-border-light`, and `--color-icon-disabled`; it also participates in mode inference and shared `statusBg`. The error/success/warning/primary `*-bg` and `*-border` variables all use that same `statusBg`. Background/mode also influence `--color-highlight-active-match` (through the semantic yellow fallback/mode) and several other semantic and graph colors. `--color-bg-scrollbar-thumb` is derived from muted text, so it belongs with Text rather than being presented as a background-only output.
  - **Text (`base.text`)** supplies `--color-text-default`, `--color-text-dark`, `--color-icon-default`, and `--color-icon-dark`; through `muted` it drives `--color-text-light`, `--color-icon-light`, `--color-bg-scrollbar-thumb`, and the minimap muted surfaces; it also drives `--color-text-strong`, grid text, and graph label/link text. `--color-icon-disabled` is a shifted background color, not a text output, so show it with Background. The text/background badge is the existing `text-default/bg-default` entry returned by `contrast()`.
  - **Accent (`base.accent`)** drives selection and tree-selection fills, active border/icon, `--color-misc-blue`, grid selection fills/borders, `--color-minimap-active-bg`, primary text and primary hover text, graph highlight/group/border-highlight values. It does not drive primary background/border (those are `statusBg`) or `--color-highlight-active-match` (that uses the semantic yellow fallback and mode); show those with Background/shared surfaces, not Accent.
  - **Optional `base.link`** supplies `--color-misc-link`; when absent, Persephone derives the link from mode and background. **Optional `base.error`, `base.warning`, and `base.success`** supply their respective `*-text` and derived `*-text-hover`; when absent, Persephone derives those text values from mode and `statusBg`. For all four status families, `*-bg` and `*-border` are the shared background/mode `statusBg`, not outputs of the optional color. Keep those shared fill/border swatches in Background; each semantic block owns its text and hover-text swatches. All four optional base keys are absent by default, which is Auto.
- The existing optional base controls already treat an empty value as absence (`delete state.draft.base[key]`), and `clearOverrides` empties `state.draft.overrides` and refreshes the draft. Preserve this behavior for status Auto and pinned overrides. `fork(id)` preserves a built-in's exact appearance using a base plus overrides, so the source selector needs an explicit fork choice when Generator is active.

## Concerns / Open Questions

- Source base colors are supported CSS color strings, while the generator's sliders and hex field represent opaque RGB. For supported non-hex/alpha base values, preserve the original string until the user edits the control; when a slider edit necessarily converts it to opaque hex, make that conversion visible (or retain alpha with an explicit alpha control if the browser-side color conversion can do so reliably). Do not silently rewrite a source color just by opening Generator.
- A built-in fork may contain many overrides; the Exact copy option can therefore show pinned outputs and may fail one or more randomized contrast pairs. The pinned count, per-token pin markers, Clear action, bounded retries, and best-candidate message make this state visible without discarding exactness.
- Contrast retries are bounded at 20 calls per generation action. The bridge calls remain serialized by the existing refresh chain after candidate selection; avoid firing `preview()` for each rejected candidate.
